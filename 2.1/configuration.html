Configuration ​

An instance's settings live in its state.json and change only through fieldset config set. fieldset renders the Compose project and the environment files (compose.yaml, env/*.env) from that state and checks every change before it keeps it. Do not edit env/ or compose.yaml by hand: the next fieldset command rewrites them, and a hand-made change bypasses the checks and the automatic revert.

The 1.0 reference of .env variables for checkout installs is in the archive.

Show and change settings ​

sh
fieldset config show                       # every setting, the keys you can set in this mode, outbound contacts
fieldset config set <key> <value>          # change one setting

fieldset config set validates the value, runs the checks the change needs (DNS, ports, the SMTP server), applies it, restarts only the services whose configuration changed and verifies the instance. If the verification fails, the change is reverted and the command exits 5 rolled_back; errors[0] names the cause and data.fix_first or data.retry_after says what to do. Setting a value that is already set changes nothing. Changes that move the instance to another URL ask for confirmation first (--yes confirms).

Mail ​

New instances capture mail in the instance's mail catcher (Mailpit); the admin dashboard shows a banner while they do (see the admin guide). Switch to an SMTP server:

sh
fieldset config set mail smtp --smtp-host smtp.example.com --smtp-username forms@example.com --password-file ~/smtp-password --from-address forms@example.com --test-to you@example.com
  • The password comes from --password-file <file> or --password-stdin (piped, or a hidden prompt on a terminal), never from the command line.
  • --smtp-port (default 587), --smtp-encryption starttls|tls|none (default starttls; tls is implicit TLS on 465, none only for a relay in a trusted network), --from-name.
  • fieldset sends a test mail through the new server (to --test-to, or the operator) and keeps the change only if the server accepts it; otherwise it reverts with exit 5 test_mail_failed.
  • The catcher keeps running so you can still read captured mail; --remove-catcher removes it and its data.
  • fieldset config set mail capture goes back to capturing.
  • fieldset config show --catcher-login --secrets-file <file> writes the catcher's login to a file.

Organizations can also use their own SMTP server for their mail ("E-Mail-Einstellungen" in the admin dashboard). Invitations, password resets and e-mail confirmations always go through the instance's mailer.

What fieldset sets for you ​

The rendered environment always runs the app in production mode with debug off, registration off, encrypted database sessions, PDF rendering through the instance's Gotenberg, secure SSO settings and exactly one trusted proxy address for the mode (the edge in domain and local-CA mode, the proxy container in proxy mode, none otherwise). The database, Valkey and catcher passwords and the APP_KEY are generated at install and never printed.

Settings of the 1.0 .env that fieldset config set does not offer (for example error reporting, upload scanning or log channels) are not configurable on a 2.0 instance. fieldset adopt takes over only the APP keys, the URL (and with it the mode and port), the sender and the database names from a 1.0 .env; everything else comes from fieldset's rendering. Mail starts captured: the 1.0 SMTP server is only suggested for fieldset config set mail smtp.

Organization settings ​

Everything that belongs to one organization (branding, members, SSO, mail settings, retention, webhooks, API tokens) is set in the admin dashboard; see the admin guide.
