Archive (1.0): Configuration reference ​

Archive. This is the 1.0 guide for an installation from a clone of the repository with Docker Compose (a "checkout install"). It describes 1.0 under the product's former name, form-schema-app; the product is now Fieldset. It does not apply to an instance installed with install.sh and managed with fieldset (2.0): do not run its git, docker compose, migration, restore or .env steps on such an instance; they bypass fieldset's backups, maintenance gate and rollback. For 2.0 see the current guide. To move a checkout install to 2.0, use fieldset adopt (install guide). Where this guide names the 2.0 tool fsa, read fieldset.

All settings are environment variables in .env, read through the files in config/. Every service in compose.yaml loads .env; values in .env override the defaults built into the image. After a change, recreate the containers: docker compose up -d --force-recreate app queue scheduler (the configuration is cached when a container starts).

"Default" is the value the application uses when the variable is not set. Where .env.example (development) or .env.production.example (the production template) sets a different value, the table says so. Settings marked fixed are configuration keys without an environment variable; changing them means editing config/ and rebuilding the image.

Logging and error reporting ​

config/logging.php

VariableDefaultMeaning
LOG_CHANNELstderr (image); both templates: stackstack sends logs to the channels in LOG_STACK. stderr writes to stderr with LOG_STDERR_FORMATTER.
LOG_STACKsingle; production template: jsonChannels of stack, comma-separated. json: one JSON object per line on stderr. single: a file inside the container, lost when it is recreated. Add sentry for error reporting, for example json,sentry.
LOG_LEVELdebug; production template: infoinfo or warning in production.
LOG_STDERR_FORMATTERApp\Support\Logging\JsonLogFormatter (image)Formatter of the stderr channel.
LOG_JSON_STREAMphp://stderrWhere the json channel writes.
LOG_DEPRECATIONS_CHANNELnullPHP deprecation warnings.
SENTRY_DSNemptyDSN of a Sentry-compatible service (Sentry, GlitchTip and others), used by the sentry log channel: add sentry to LOG_STACK (with LOG_CHANNEL=stack). Without a valid DSN the channel discards everything.
SENTRY_LEVELerrorLowest log level that is reported.
SENTRY_ENVIRONMENTAPP_ENVEnvironment name on each event.
SENTRY_RELEASEemptyRelease name on each event.
SENTRY_TIMEOUT2Seconds per report.

Every request gets an X-Request-Id (taken from the request or generated), which appears in the logs.

The JSON lines contain @timestamp, level, message, channel, service, environment, request_id, the context and exception traces. Passwords, tokens, secrets and credential headers are redacted, and database errors never contain the query's values. Error reports to SENTRY_DSN carry the exception, the request id and the user id, but no request data. They are sent from the app, queue and scheduler containers, so allow outbound HTTPS to the DSN host if outbound traffic is restricted.

Security headers and proxies ​

config/security.php, config/trustedproxy.php. Background: install guide, step 5.

VariableDefaultMeaning
TRUSTED_PROXIESempty (no proxy is trusted); production template: 172.16.0.0/12IP addresses or CIDR ranges, comma-separated. Only these may set X-Forwarded-For, -Proto, -Host and -Port. The template's range is the Docker bridge range, from which a reverse proxy on the host arrives at 127.0.0.1:8080. Widen it only to the range your proxy actually connects from; never trust a range that untrusted clients can reach.
TRUSTED_HOSTSemptyExtra host names, comma-separated, besides the host of APP_URL and loopback names. Other hosts get 400 unless APP_ENV is local or testing.
SECURITY_HSTS_ENABLEDempty (automatic)Empty: send Strict-Transport-Security when the request is HTTPS or APP_URL is https://. true: always. false: never.
SECURITY_HSTS_MAX_AGE31536000 (one year)Seconds.
SECURITY_HSTS_INCLUDE_SUBDOMAINS, SECURITY_HSTS_PRELOADfalse, falseAdd includeSubDomains / preload. Only if every subdomain serves HTTPS.

Admin panel sessions end after 30 minutes without activity (idle timeout) and 12 hours after the sign-in at the latest (absolute timeout). Both are set in config/security.php:

VariableDefaultMeaning
SECURITY_ADMIN_IDLE_MINUTES30Minutes without an admin request (page or Livewire update) before the admin session ends.
SECURITY_ADMIN_ABSOLUTE_HOURS12Hours after which the admin session ends, active or not.

The Field App session is not affected: it keeps SESSION_LIFETIME (30 days, rolling). The browser has one session, so someone who returns to /admin after a timeout is signed out of that browser completely and signs in again.

Fixed: the Content Security Policy per area (admin and /platform, Field App, builder preview, API, Horizon, API documentation), X-Content-Type-Options: nosniff, Referrer-Policy: same-origin, X-Frame-Options, a Permissions-Policy that allows only camera and location, and only for the Field App. The admin pages load no scripts, styles, fonts or images from other sites.

VariableDefaultMeaning
UPLOADS_CLAMAV_ENABLEDfalseScan these uploads before they are stored.
