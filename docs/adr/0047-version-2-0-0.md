# 0047: Version 2.0.0 for the Docker distribution
- Status: accepted
- Date: 2026-10-17

## Context
BUILD_PROMPT_V2 §0 E1 sets the version for the M9–M13 work. 1.0.0 is tagged `v1.0.0` on `main`. Today
`package.json` (`"version": "1.0.0"`) is the only version marker, and the image has no OCI labels (Appendix C).
2.0 changes how the app is installed and operated: prebuilt images, the `fsa` command and generated compose
projects replace the checkout-based install described in `docs/guide/install.md`.

## Decision
- The release is **2.0.0**, a SemVer major. The major covers the install and operations contract. A checkout-based
  1.0 install becomes an instance only through `fsa adopt` (R46, changed by plan R60 to copy the volumes) or
  `fsa install --from-backup` with a 1.0-format archive. Nothing upgrades a checkout in place.
- Unchanged: Form Schema Spec 1.0, the `/api/v1` contract and the Field App contract (§6.6). The data model only
  moves forward, and a 1.0.x database upgrades through the normal migrations.
- One pre-release per milestone, built and tagged locally only (§12, ADR 0064): `2.0.0-alpha.1` (M9),
  `2.0.0-alpha.2` (M10), `2.0.0-beta.1` (M11), `2.0.0-rc.1` (M12), then `2.0.0` (M13).
- The version enters the image through the `APP_VERSION` and `APP_REVISION` build arguments. They are exposed as
  `config('app.version')`, OCI labels, the `/platform` instance page and `fsa version` (plan KTD9).
- Image tags are `X.Y.Z`, `X.Y`, `X` and `latest`. A pre-release publishes only its own tag and never moves the
  others (§6.5).
- `fsa upgrade` stays within the installed major unless `--major` is given (R33, ADR 0058).

## Alternatives considered
- **1.1.0:** the API and the Spec stay compatible, so API clients would accept a minor. Rejected: operators of
  checkout installs get a different install, upgrade and backup path, and SemVer should warn them.

## Consequences
- The 1.0 install, upgrade and backup guides move to an archive section (R52). Checkout installs keep working for
  development. `scripts/backup.sh` and `scripts/restore-drill.sh` stay for checkouts (§6.6).
- The release manifest records the oldest version it upgrades from (R2). Older sources exit 7.
- API consumers change nothing. The release notes say so explicitly.
