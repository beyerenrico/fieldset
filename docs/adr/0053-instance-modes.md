# 0053: Three instance modes: local, domain and proxy
- Status: accepted
- Date: 2026-10-17

## Context
E7. §2.3 names three targets: a VPS with a DNS name, a local machine, and an existing Docker host that already
has a proxy. Each should get one predictable shape, not a combination of flags.

## Decision
| Mode | Selected by | Edge | Published ports | Instance URL | Trusted proxy |
|---|---|---|---|---|---|
| local | default without `--domain` | no | loopback port, 8080 or the next free one (R15) | `http://localhost:<port>` | none |
| local + local CA | `--phone-https local-ca` | yes | 80/443 on the LAN address only | `https://<LAN address>` | edge address |
| local + tunnel | `--phone-https tunnel` | no | loopback port | the tunnel host while active, otherwise local | cloudflared address |
| domain | `--domain` | yes | 80, 443, 443/udp | `https://<domain>` | edge address |
| proxy | `--behind-proxy traefik\|caddy\|port`, `--url` | no | loopback port, or none on a shared network | `--url` | the proxy's exact address |

(Table from the plan's "Mode and option combinations".)

- In domain mode only the edge publishes ports. Postgres, Valkey, Gotenberg and Mailpit never do (§10).
- Proxy mode joins a named external network with Traefik or caddy-docker-proxy labels, or publishes a loopback
  port. Only the proxy's own address is trusted, not its neighbours on that network. Trusted hosts come from
  `--url` (R17).
- Tunnel, local CA, domain and proxy exclude each other, and combining them exits 2 (plan R61).
- The mode lives in the instance state. `config set` changes mode, URL, port and trusted proxies with
  apply, verify and revert (plan U11).
- The app resolves its public URL, trusted hosts, Sanctum stateful domains, HTTPS expectation and cookie security
  per request and per job (plan R56, KTD11). It reads them from a read-only runtime directory that `fsa` writes,
  so a URL change needs no rebuild and a tunnel expiry needs no restart.
- The Portainer/Coolify stack file is generated by the same renderer as proxy mode (R18). It is configured only
  through environment variables, and its limits are documented.

## Alternatives considered
- **One mode with many flags:** the combinations multiply, and no target gets a predictable shape.

## Consequences
- Catcher UI: a loopback port in local and proxy modes, `/_mail/` behind the edge in domain mode (ADR 0054).
- The upgrade gate is app-level, so it works in every mode (ADR 0058).
- A URL change breaks signed links, and installed home-screen apps keep the old address. `fsa` warns about both
  (R21). `config set domain` needs `--yes` and lists the SSO organizations, whose SAML entity IDs follow the URL.
- In HTTPS modes the session cookie becomes `__Host-`.
