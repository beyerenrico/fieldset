# form-schema-app 1.0.0: the first stable release (2026-10-23)

1.0 completes the plan for version one. It adds single sign-on and the canvas builder (M7), and it
hardens the platform for production (M8): an append-only audit log, GDPR tools, security headers,
integration tokens and an operator panel.

## Highlights
- **Sign in with your company account.** Organizations connect Microsoft Entra ID, Google Workspace, any
  OpenID Connect provider or a SAML 2.0 provider. After verifying their email domains by DNS, they can
  create accounts at the first sign-in, map groups to roles, and require single sign-on, with a
  break-glass Owner for emergencies.
- **The canvas builder is the default.** Forms open in the drag-and-drop canvas builder, which works
  fully with the keyboard and loads in a fraction of the classic builder's time. The classic builder is
  one click away; it still holds form access, the versions table and the PDF import report.
- **An audit log you can rely on.** "Compliance" → "Audit-Log" shows who did what and when, with filters,
  CSV export and a history on forms, submissions, workflows, members and SSO. The database refuses
  changes and deletions, and every entry is sealed into a hash chain per organization. With the chain
  heads from `audit:verify --heads` shipped to storage outside the database, changes become visible even
  if someone with database access recomputed the chain. Entries are kept for 365 days by default.
- **Data protection built in.** Set a retention period per form: after it, submissions are deleted or
  anonymized every night, so reports keep their numbers without personal data. Legal holds keep invoices
  and other records that must be kept. Admins export a member's personal data as a ZIP file or erase the
  account; dashboard users can do both for themselves under "Meine Daten" ("My data").
- **Connect other systems.** Personal API tokens with abilities per resource, bound to one organization,
  with their own rate limit. Creation, revocation and first use are audited.
- **Safer by default.** Admin sessions that time out (30 minutes idle, 12 hours at most), a Content
  Security Policy on every page, HSTS and Secure cookies behind HTTPS,
  trusted proxies and a host allow-list, a sandboxed builder preview, optional ClamAV scanning of uploads,
  JSON logs with secrets redacted, and optional Sentry-compatible error reporting.
- **For operators.** The `/platform` panel lists organizations, checks the health of queues, PDF
  rendering, mail, scheduler and disk, and lets operators sign in as an admin member for support, with a
  reason and a time limit; the organization's audit log shows the start, the end and the operator behind
  every action taken meanwhile. New guides cover install, upgrade,
  backup and restore drills, configuration and troubleshooting.

## Performance
Measured with 100k submissions, 2.3M values and 150k audit entries in one organization (30 runs per page
or endpoint; details in `docs/agent/milestones/evidence/M8/performance.md`):

| Target (§11) | Result (p95) |
|---|---|
| Admin pages < 500 ms | 26 of 27 page types pass, the slowest at 365 ms (a saved report over all submissions). The classic builder takes 1.05 s (exception below) |
| API < 300 ms | All 23 measured series pass, the slowest at 125 ms |
| 10-page PDF < 10 s, queued | 2.3 s from dispatch to the stored file |
| 300-element form, 500-row repeater responsive | Canvas builder with 310 elements: 21 ms per operation. Field App at 4× CPU throttling: typing 32 ms (300 elements), 136–168 ms in a 500-row repeater |
| Field App first load < 3 s over 4G | 2.07 s on slow 4G with 4× CPU throttling (209 kB of JS and CSS, gzip). Repeat loads come from the cache (0 kB) |

Accepted exceptions (ADR 0046): the classic builder page (1.05 s; the canvas builder is the default), the
Field App first load under Lighthouse's stricter "devtools" throttling (3.5 s), and adding the 501st
repeater row (median 203 ms at 4× CPU).

## Upgrade notes
Follow the [upgrade guide](../guide/upgrade.md). In short:
- Back up first and run a restore drill (`scripts/backup.sh`, `scripts/restore-drill.sh`).
- The app port is published on `127.0.0.1` only, so the TLS reverse proxy runs on the host. `APP_PORT` is
  a port number only. Set `TRUSTED_PROXIES=172.16.0.0/12` (the Docker bridge range, as in the template);
  empty trusts no proxy and links use `http://`. Requests for host names other than the one in `APP_URL`
  now get 400; list extra names in `TRUSTED_HOSTS`.
- Admin sessions now end after 30 minutes without activity and after 12 hours; the Field App is
  unchanged.
- New settings come with safe defaults; compare your `.env` with `.env.production.example`.
- The migrations make the audit log append-only. `activitylog:clean` no longer works; `audit:prune`
  replaces it. Existing entries are sealed into the hash chain by `audit:seal` over the first runs.
- New scheduled tasks: audit sealing (every 5 minutes), retention (02:30), audit pruning (03:15), and
  daily clean-up of exports and expired tokens. The `scheduler` service must run.
- Rebuild the image (the Caddyfile changed for the sandboxed preview) and recreate the containers, which
  restarts Horizon.
- Integrators: the PDF of an anonymized submission answers 410 `document_anonymized`; treat it as final.

## Known limitations
- One identity provider per organization, and no single logout (RP-initiated logout or SAML SLO).
  Break-glass sign-ins are audited but not notified.
- SSO from the installed iOS app is untested; if it fails, start the sign-in in Safari (QUESTIONS #18).
- Web push is deferred past 1.0 (ADR 0045, QUESTIONS #19). Notifications are in-app and by email.
- Accessibility: automated WCAG 2.2 AA scans and keyboard walkthroughs pass, but screen readers, zoom and
  real devices still need human testers. Handwritten signatures need a pointer; there is no typed
  signature (QUESTIONS #20).
- Background Sync only wakes open tabs; on iOS the Field App syncs when it is opened (QUESTIONS #13).
- The Field App has no screen for personal data export or account deletion; field workers ask an Owner
  or Admin. Devices may keep copies of anonymized or deleted submissions until their next sync.
- Audit entries written before an erasure or anonymization keep their values until audit retention
  removes them.
- In the default Docker setup the application's database role is a superuser, so the append-only trigger
  does not stop someone with database access. The hash chain uses no secret key, so such a person could
  recompute it; only chain heads shipped regularly outside the database detect that. The install guide
  describes the shipping and a hardened setup with a maintenance role.
- `/horizon` and the API documentation are still gated by `PLATFORM_ADMIN_EMAILS`, not by the operator
  role. The audit entries for granting and revoking the operator role belong to no organization and are
  visible only in the database.
- The admin pages' Content Security Policy keeps `'unsafe-eval'` (needed by Alpine and Horizon), and the
  API documentation page loads its scripts from unpkg without subresource integrity.
- Form access, the versions table and the PDF import report exist only in the classic builder.
- No e-invoice output (ZUGFeRD, XRechnung) (QUESTIONS #3). Decisions waiting for human review are listed
  in `docs/agent/QUESTIONS.md`.
