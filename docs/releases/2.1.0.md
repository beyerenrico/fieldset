# Fieldset 2.1.0: the first published 2.x release, renamed from form-schema-app (2026-10-23)

2.1.0 is the first published release of the 2.x line and the first under the name Fieldset. 2.0.0 was tagged locally
and not published, so 2.1.0 is also the first release that carries 2.0's Docker distribution and the `fieldset`
tool. Apart from the rename and a few fixes, 2.1.0 changes no behaviour.

## Highlights
- **The product is called Fieldset.** form-schema-app is renamed before its first public release. The repository is
  `beyerenrico/fieldset`, the image `ghcr.io/beyerenrico/fieldset`, the signer identity
  `https://github.com/beyerenrico/fieldset/.github/workflows/release.yml@refs/tags/v…`.
- **The tool is `fieldset`, not `fsa`.** The shim, the artisan namespace (`fieldset:*`), the installer link and the
  default directories (`/opt/fieldset`, `~/fieldset`) change, and the environment variables are `FIELDSET_*` (were
  `FSA_*`).
- **A docs site.** [beyerenrico.github.io/fieldset](https://beyerenrico.github.io/fieldset/) has one copy of the guides
  per minor version, search, the Field App API contract, an interactive API reference that sends no requests, the
  changelog and Fieldset Spec 1.0 with its meta-schema.
- **Fixes.** A second classic-builder render waits up to 20 s and then gets a 503, instead of two renders pushing the
  `small` app over its memory limit. The MFA set-up QR code is always SVG. A canvas builder drop no longer leaves the
  inspector on the previous element. The first central login in the Field App with SSO no longer fails with "The
  central login did not work". Docker Compose before v5 also passes `docker compose up --wait` on an instance.
- **Security.** The app image is built with Go 1.27.3 and the Docker CLI 29.9.2, and cloudflared moves to 2026.10.2,
  for CVE-2026-111943 in Go's `crypto/x509`. The postgres, Gotenberg, Mailpit and Caddy images have no release with the
  fixed Go yet: dated scan exceptions until 2026-11-20. Gotenberg 8.38.1 carries 60 high Chromium findings, with
  scan exceptions until 2026-11-22 (ADR 0071, 0093).

## Upgrade notes
**The rename is breaking for every pre-release user, and there is no compatibility path.** Old names are removed, not
aliased (ADR 0092).
- **2.0 pre-release instances are not upgraded.** `release.json` upgrades from `2.1.0-alpha.1` only. A backup written
  by a 2.0 pre-release is rejected as an unknown format, because the backup, audit-export and security-export
  formats and the backup key derivation use the new name.
- **Instance resources are renamed:** Compose projects `fieldset-<slug>-<hex>`, labels `app.fieldset.*`, the marker file
  `.fieldset-instance`, and database and role names `fieldset*`. Scripts, monitoring and rules
  that match the old names (`fsa`, `FSA_*`) need the new ones.
- **SSO domains must be verified again.** The DNS TXT record is now `_fieldset-verification.<domain>` with the value
  `fieldset-verification=<token>`.
- **Field App devices:** browser storage, sync and preview message names use the new prefix. Unsynced data on a phone
  that ran 1.0 must be synced before switching.
- **1.0 installs** from a clone of the repository still move with `fieldset adopt` (its 1.0 project and database
  defaults are kept); see the [install guide](../guide/install.md#adopt-a-10-install).
- **Integrators:** the PHP package is `fieldset/fieldset-php` (namespace `Fieldset\`), the npm workspaces are
  `@fieldset/fieldset-js`, `@fieldset/fieldset-react`, `@fieldset/field-app` and `@fieldset/builder-v2`, the spec's
  `$id` is `https://beyerenrico.github.io/fieldset/spec/form-definition/1.0/meta-schema.json`, and the template registry
  is `urn:fieldset:bundled-templates`. Fieldset Spec 1.0 keeps its version; nothing in it changes semantically.

New installs follow the [install guide](../guide/install.md); later releases upgrade with
[`fieldset upgrade`](../guide/upgrade.md). For what 2.0 introduced, see the [2.0.0 note](2.0.0.md). The full list of
changes is in the [changelog](../../CHANGELOG.md).
