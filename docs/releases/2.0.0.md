# form-schema-app 2.0.0: Docker distribution and the `fsa` tool (2026-10-21, tagged locally, not published)

**2.0.0 was tagged locally and never published.** No image, installer or release notes were released under this
version. The first published 2.x release is [2.1.0](2.1.0.md), which renames the product to Fieldset and the tool from
`fsa` to `fieldset`. Install or adopt with 2.1.0 or later; this note records what 2.0 introduced, and the commands
below use the current name `fieldset`.

2.0 changes how Fieldset is installed and operated. You no longer clone the repository: one command installs a signed
release, and one tool configures, backs up, restores, upgrades, rolls back, resets and removes the instance, with JSON
output and documented exit codes for agents and scripts.

## Highlights
- **Install from a signed release.** `install.sh` downloads the release manifest, checks its signature, pulls the images
  by digest and hands over to the instance's command-line tool. Local, domain and proxy modes, mail capture or SMTP,
  demo data and phone HTTPS are part of 2.0 (listed in the 2.0 pre-release entries of the [changelog](../../CHANGELOG.md)).
  See the [install guide](../guide/install.md).
- **Backups on by default.** Every instance runs a `backup` service: a backup every day at 03:30 in the instance's time
  zone, the newest 7 scheduled backups kept. A backup holds the database, the files, the portable settings and the audit
  chain heads, and counts only once its dump reads back. Backups can be encrypted with an age key pair. `fieldset status`
  and the `/platform` panel warn about failed or stale backups, and every platform operator gets one e-mail per failed
  or stale backup. See [backup and restore](../guide/backup-restore.md).
- **Restore, drill and move.** `fieldset restore` checks a backup before it writes anything, takes a safety backup, and
  keeps the old instance when the restored one does not pass its checks. `fieldset restore --drill` tests a backup
  in a scratch database without touching the instance. `install.sh --from-backup` moves an instance to another host.
- **Upgrade and rollback.** `fieldset upgrade` verifies the target release, drains the queue behind a maintenance
  gate, takes a verified safety backup, migrates, runs a smoke test and rolls back by itself when anything fails. It
  runs in a background container, so a closed SSH session does not stop it. `fieldset rollback` returns to the previous
  release from that safety backup. See the [upgrade guide](../guide/upgrade.md).
- **Adopt a 1.0 install.** `fieldset adopt <checkout>` turns a clone-based 1.0 install into an instance with its data,
  keeps APP_KEY, and starts 1.0 again if anything fails before 2.0 starts.
- **Reset.** `fieldset reset` returns an instance to a fresh state (or to the demo data) after a safety backup.
- **Instance page and update check.** "Instanz" ("Instance") in `/platform` lists problems first (failed or stale
  backup, low disk space, available update, backups held only on this host), each with its command. The update check is
  off by default (`fieldset config set update-check on`); when on, the app reads the release manifest once a day and
  sends nothing else.
- **For agents.** The [agent guide](../guide/agent-guide.md) has recipes with exact commands, the JSON fields to read,
  exit codes and recovery fields; its runnable blocks are executed against a locally built release in CI.

## Upgrade notes
- 2.0.0 cannot be installed or upgraded to: nothing was published under it. Use [2.1.0](2.1.0.md) or later.
- A 1.0 install from a clone of the repository moves with `fieldset adopt`; see the
  [install guide](../guide/install.md#adopt-a-10-install). It stops 1.0's services, copies the database and files into
  the instance's own volumes and checks the copy. A Compose override, an external database or a Postgres other than 16
  on Alpine is refused (exit 7). The 1.0 guides moved to `docs/guide/archive/`.
- Only the settings that `fieldset` renders are configurable. Of a 1.0 `.env`, adopt takes over the APP keys, the URL,
  the sender and the database names; the debug, SSO and trusted-proxy values are never applied, and mail starts
  captured. See [configuration](../guide/configuration.md#what-fieldset-sets-for-you).
- Back up and copy backups off the host after the move, and run a restore drill
  (`fieldset restore <backup> --drill`).

The full list of changes is in the [changelog](../../CHANGELOG.md), including the 2.0.0 pre-releases that were also
never published.
