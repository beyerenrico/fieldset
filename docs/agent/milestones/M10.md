# M10 Modes → 2.0.0-alpha.2: gate report (2026-10-18)

Architecture: ADRs 0074–0079 record the M10 decisions: 0074 (instance runtime state in the app: URL, gate, tunnel
policy), 0075 (edge and domain mode), 0076 (proxy mode and the stack file), 0077 (`fsa config`), and from the gate
0078 (config safety and the agent contract of `fsa config`) and 0079 (edge and runtime hardening). The gate amended
ADRs 0040, 0052, 0054, 0065, 0066, 0069, 0070, 0072 and 0074–0077. U8 and U9 ran in parallel worktrees, merged
with `--no-ff` (abf5fd1, 86eca37). The gate fixes ran on side branches, merged with `--no-ff` (72ab75a, 5b89426).

## What was built
### Runtime state in the app (U10, M10-T01)
- `App\Domain\Instance\Runtime` reads `runtime.json` from the read-only runtime directory. The grammar is strict
  (`RuntimeDocument`). The reader never throws and caches on path, inode, size and mtime. It keeps the last good
  value; without one it falls back to APP_URL and the gate counts as raised (fail closed). It imports no ops
  namespace, and `InstanceBoundaryTest` treats every other instance directory as ops.
- `ResolveInstanceRuntime` is global middleware, placed before `SecureCookies`:
  - A request from cloudflared's address counts as a tunnel request, whatever its headers say. Its host is pinned
    to the runtime tunnel host, with https.
  - An expired or missing tunnel gets 503 with `Retry-After: 300`. A path outside the R65 allow-list gets 404;
    `/admin` is reachable only with `tunnel.admin`.
- Gate: 503 with `Retry-After: 30`. Two exemptions: `/up` from loopback, and the operation's smoke token
  (`X-Fsa-Smoke-Token`) from a private address, never through the tunnel.
- URL root: the request's origin on allowed hosts, otherwise the public URL. `TrustedHosts` adds the runtime hosts.
  The allowed hosts join Sanctum's stateful domains. HSTS, Secure cookies and `upgrade-insecure-requests` follow
  the scheme resolved for the host. HTTPS modes use a `__Host-` session cookie.
- `ApplyRuntimeToJob` (`JobProcessing`) points jobs, queued mails and notifications at the current public URL
  without a worker restart. `/platform/health` has a `runtime` check (DE/EN).
- `RuntimeWriter` writes the gate with a smoke token and an empty tunnel block for U14. Checkout installs (no
  `FSA_RUNTIME_PATH`) behave as before.

### Edge service and domain mode (U8, M10-T02)
- `EdgeService` runs the pinned Caddy digest:
  - As UID 65532 with only `NET_BIND_SERVICE` and a read-only root. It publishes 80, 443 and 443/udp, and nothing
    else publishes a port in domain mode.
  - At a fixed address on a /28 from 10.213.0.0/16 (`EdgeNetwork`), chosen once per instance and kept out of
    Docker's dynamic range. App and Mailpit join that network, and the edge address is the app's only trusted
    proxy.
  - With certificates on the labelled volume `<project>_edge-data`, which only uninstall removes. A label carries
    the Caddyfile's hash, so a changed Caddyfile recreates the edge.
- `CaddyfileRenderer` builds the Caddyfile as a tree. Values are quoted, and unsafe ones are refused (exit 1
  `unsafe_caddyfile`). The admin API and config autosave are off. `acme_ca` is always set: Let's Encrypt production
  by default, or `--acme-staging`, `--acme-ca` and `--acme-ca-root-file`. Automatic HTTPS redirects with 308, and
  the app is proxied unchanged.
- `/_mail/` sits behind `forward_auth` to `/_fsa/catcher-auth` (`CatcherAuthController`, `CatcherAccess`):
  - Access needs an active operator with a valid `/platform` session, confirmed MFA and the current password hash.
    The route reads the session without writing it.
  - `platform.catcher_opened` is audited once per session. Without access a navigation gets 302 to the `/platform`
    sign-in, anything else 401.
  - The edge injects Mailpit's Basic auth and adds framing, nosniff, CSP, Referrer-Policy and no-store headers. The
    Mailpit spike came first (LEARNINGS 103).
- `fsa install --domain` is enabled:
  - Preflight: the ACME flags, then ports 80/443; a rootless engine that may not publish them is named with the
    sysctl. The doctor phase journals the mode.
  - The smoke test waits for the certificate on the edge's own network, with the domain as SNI. Without a
    certificate it is exit 4 `certificate_failed` with the edge log. The certificate volume stays, and install
    resumes at the smoke test.
  - `fsa status` reports `port: null` and the catcher URL. Uninstall warns about Let's Encrypt's
    duplicate-certificate limit.
- Harness: Pebble and challtestsrv 2.10.1 in the `acme` profile. `FSA_TEST_DNS` pins the doctor's DNS answers, and
  only harness images honour it.

### Proxy mode and the stack file (U9, M10-T03)
- `fsa install --behind-proxy traefik|caddy|port --url <origin>`. Traefik and caddy also take `--proxy-network` and an
  optional `--trusted-proxy`.
  - The doctor phase finds exactly one proxy address through the engine: the named container, or the only Traefik or
    caddy-docker-proxy container on the network. Zero or several candidates exit 3 with nothing changed.
  - The `port` setup trusts the default network's gateway, read after Compose creates the network.
- The renderer has a `proxy` mode:
  - Only the app joins the external network, which Compose neither creates nor labels.
  - The app gets Traefik labels (router by the `--url` host, TLS for https), caddy-docker-proxy labels, or a
    loopback port.
  - The catcher UI stays on loopback in every setup. `TRUSTED_PROXIES` holds a single address.
- Stack file (R18): `StackFile` renders a `port`-setup state with the release digests through `ComposeRenderer`:
  - Configuration is env-only: secrets as `${VAR:?…}`, images as `${FSA_REGISTRY:-…}/…@<digest>`.
  - `YamlEmitter` writes block YAML. The header documents the variables and what is missing without `fsa`.
  - `release:manifest --stack-file` writes it as an asset listed in the signed manifest, and `release.yml`'s sign
    job checks it. A drift test compares it with the proxy-mode render.
- Harness: Traefik v3.7.15 in the `proxy` profile, on an external `fsa-test-proxy-<id>` network.

### `fsa config` (U11, M10-T04)
- `fsa config show` reads only the state:
  - Secrets appear by name as `[redacted]`.
  - Every key shows its value, `changes_url` or `arrives_with`.
  - `outbound_contacts` names what each opt-in feature contacts (§10).
- `fsa config set <key> <value>` takes these keys: `domain` (with the ACME options), `url`, `port`,
  `trusted-proxy` (`auto` re-resolves), `mode local`, `acme-email` and `acme-ca`. Later keys (`mail`,
  `operator-email`, `backup-*`, `update-check`) get exit 2 `setting_not_available` with the release that brings
  them.
- Flow:
  - The same value again is `changed: false`, with no Docker call and no journal.
  - A URL change needs confirmation. The one-off `instance:url-impact` lists organizations with SSO and counts the
    links that keep the old address. Without `--yes`, exit 6.
  - Under the lock and journal: snapshot, preflight (exit 3), apply (render, `compose up --wait
    --remove-orphans`), verify (the install smoke test, certificate and redirect, the proxy URL's Host), then audit
    `instance.config_changed` through a socket-less one-off (DE/EN labels).
  - A failure reverts to the snapshot. A failed revert is exit 8.
- A resume starts from the journaled snapshot and preflight target, and only for the same request.

### Gate fixes
- `fsa config` (ADR 0078):
  - A reverted change is exit 5 `rolled_back`, retryable per cause.
  - SIGTERM, SIGINT and SIGHUP handlers start the revert.
  - Certificate progress per attempt, and phases report their duration.
  - Queue and scheduler stay stopped until the change is verified (`workers` phase).
  - New resume and failed-revert rules, and new agent contract fields.
- Doctor and status: a `proxy` drift check and `data.proxy`, IPv6 probes for the edge's ports, a stricter
  privileged-port rule, and an uninstall certificate warning that follows the volume.
- Runtime and edge (ADR 0079):
  - The in-request URL root keeps the request's scheme and takes its port from the configured URL.
  - The edge strips `X-Forwarded-Port`, and `Cookie` and `X-XSRF-TOKEN` towards Mailpit.
  - The edge label includes the CA root.
- Migrations: `migrate --isolated=75` with `MigrationMutex`; `ConcurrentIndex` rebuilds invalid indexes.
- Launchers: a value flag before the command keeps its value.
- Evidence and docs: `EvidenceRedactor`, J2 forged-port checks, the stack file in `RELEASING.md`, guides, ADR
  amendments.

## Review
Five reviewer subagents: correctness, security, data safety, agent operability and docs accuracy. Both high findings
were in agent operability.

| Finding | Severity | Area | Resolution |
|---|---|---|---|
| The domain-mode certificate wait was one opaque `curl --retry 40` container: up to seven minutes without progress. A killed foreground process (agent tool timeout, SSH drop) then left an unverified configuration applied with its journal open | high | agent operability | A PHP loop runs one `curl` container per attempt (40 attempts, 5 s apart, at most 420 s), each with an NDJSON event (`attempt`, `attempts`, `elapsed_seconds`, `max_seconds`). Phases announce `max_seconds` and report their duration. SIGTERM, SIGINT and SIGHUP during apply, verify or `workers` revert the change; before any change they abort with exit 9 (f2666c6, ea0adef, 3c63199; ADR 0078) |
| Every reverted `config set` reported exit 4 `failed` with `retryable: true`, whatever the cause | high | agent operability | Exit 5 `rolled_back` with `changed: false` and `reverted: true`. `retryable` follows the cause: `retry_after` for engine errors (30 or 15 s) and interruptions (0 s), `fix_first` for everything else (ea0adef, 8fefd2c; ADR 0078) |

The repository records no per-finding severity for the rest. These medium and low findings were fixed:
- **Runtime URL and edge (72ab75a, ADR 0079):**
  - A plain-http request on an https host (a stale proxy) got an https URL root. Laravel verifies signatures
    against the request's own scheme, so every URL signed in that request failed. The root now keeps the request's
    scheme, and HSTS, Secure cookies and `upgrade-insecure-requests` still follow the host (9359f26).
  - A client could put a port into reset links through `Host` or a forged `X-Forwarded-Port`. The port now comes
    from the URL configured for the host (9359f26).
  - Caddy passed a client's `X-Forwarded-Port` to the app and to `forward_auth`, and Mailpit received the operator's
    MFA'd session cookie and the XSRF token. The edge strips them (e992f69).
  - A change of only the custom ACME CA root did not recreate the edge. The edge label now includes the root's
    SHA-256 (b79e734).
- **Migrations (72ab75a, ADR 0079):**
  - The stack file's app migrated on every start without a lock. `migrate --isolated=75` now takes a Postgres
    advisory lock (`MigrationMutex`). The entrypoint waits up to 5 minutes while another container migrates, then
    exits 75 (08c10bc).
  - A killed `CREATE INDEX CONCURRENTLY IF NOT EXISTS` left an INVALID index that every rerun skipped.
    `ConcurrentIndex` drops and rebuilds it in the four index migrations (08c10bc).
- **Launchers and stack file (72ab75a):**
  - `fsa --behind-proxy traefik install` failed with `unknown_command traefik`. The wrapper and the shim now know
    every value-taking option, and a test per script keeps the list in step (7c25191).
  - The `app:install` instruction in the stack file's header lacked `-f compose.stack.yaml` and the variables
    (b86f31e).
- **Evidence (72ab75a):** J2 evidence contained raw `Set-Cookie` values and CSP nonces. `EvidenceRedactor` now
  redacts every transcript, and J2 checks that a forged port never reaches the rendered links (f0e203d, eac2f42).
- **Config safety and agent contract (5b89426, ADR 0078):**
  - Queue and scheduler kept sending mail with a URL that was not yet verified. They now stay stopped during apply
    and verify and start in the new `workers` phase, with `stop_grace_period` 100 s (ea0adef).
  - A failed revert always claimed the old settings were back. Exit 8 now reports `revert_steps` and
    `stopped_services`, and stops only the app roles, the edge and Mailpit (ea0adef).
  - A resume could adopt another run's journal, repeat a change whose revert had failed, or be blocked by an engine
    lookup while planning. Fixed (ea0adef):
    - a live lock refuses before the URL-impact one-off;
    - a run resumes only its own journal (`Supervisor::run(accepts:)`);
    - a started revert is only finished (`resumed_revert: true`);
    - the target comes from the journal.
  - A late signal could escape failure handling, and a swallowed one was lost. A resumed run interrupted before its
    own apply now reverts what the killed run left applied (3c63199).
  - Agents lacked the exact command to repeat and which keys apply where (ea0adef, 12898e2):
    - results carry `data.command`, `data.options`, `next_commands` and `data.change`, keep `data.url` and
      `data.mode` as strings, and warn `acme_staging`;
    - `config show` keys carry `modes`, `settable_now` and `use_instead`;
    - a deferred key without a value answers `setting_not_available`;
    - a repeated install lists `data.flags` and says that proxy mode needs a reinstall;
    - comparing `--trusted-proxy` no longer loops with `config set trusted-proxy`;
    - proxy lookup failures list `data.candidates`.
- **Doctor, status, runtime and uninstall (5b89426):**
  - Proxy address drift: the doctor's `proxy` check warns `proxy_address_changed`, and `fsa status` reports
    `data.proxy` (17869c7). This closes the drift part of QUESTIONS 35.
  - When `runtime.json` could not be parsed, a re-render lowered a raised gate and dropped the tunnel block. It now
    keeps the gate raised (operation `unknown`), keeps the tunnel and refuses an unreadable file (c56fec5).
  - The uninstall duplicate-certificate warning followed the current mode instead of the edge's certificate volume
    (5738311).
  - `PortProbe` read any "permission denied" as rootless privileged ports. The edge check missed IPv6 listeners,
    and an install on a shared proxy network needed a free loopback app port it never publishes (3721ee2).
- **Docs and ADRs (3207682, a3af81f):**
  - `RELEASING.md` lists `compose.stack.yaml` as a generated release asset, with the manifest and sign jobs' stack
    file checks. Harness cleanup covers the `acme` and `proxy` profiles and Traefik's external network.
  - The configuration, install and upgrade guides name `migrate --force --isolated` and the rerunnable concurrent
    indexes (08c10bc).
  - ADR amendments: 0052, 0054, 0069, 0070, 0072 and 0074–0077 (3207682); 0040, 0065, 0066, 0070, 0072 and
    0074–0077 for ADRs 0078 and 0079 (a3af81f).
  - PLAN M10-T03 notes the stack file deviation. QUESTIONS were renumbered (34b → 35, 35 → 36, 36 → 37), and
    LEARNINGS 109 was corrected (`--remove-orphans`).
- **Found by the gate runs:** in the CI container the read-only revert test runs as root, which ignores the file
  mode. The test is skipped there (324d0be).

## Deviations
- `--proxy-network` and `--trusted-proxy` are not in §7, which names only `--behind-proxy` and `--url`
  ([ADR 0076](../../adr/0076-proxy-mode-and-stack-file.md)).
- The stack file is a release asset that `release:manifest --stack-file` generates from the manifest pins, not a
  committed `distribution/stack/compose.stack.yaml` ([ADR 0076](../../adr/0076-proxy-mode-and-stack-file.md)).
- The catcher sends `X-Frame-Options: SAMEORIGIN` and adds CSP `frame-ancestors 'self'` to Mailpit's own policy,
  instead of KTD10's `DENY`: Mailpit's Raw tab frames itself
  ([ADR 0075](../../adr/0075-edge-and-domain-mode.md)).
- The edge injects Mailpit's Basic auth (`FSA_CATCHER_AUTHORIZATION`), so the browser sees only the `/platform`
  sign-in; both layers stay ([ADR 0075](../../adr/0075-edge-and-domain-mode.md)).
- Domain mode always sets `acme_ca`, so Caddy has no ZeroSSL fallback
  ([ADR 0075](../../adr/0075-edge-and-domain-mode.md), QUESTIONS 36).
- `fsa config set` needs `--yes` for every URL change (`domain`, `url`, local `port`, `mode`), not only for `domain`
  ([ADR 0077](../../adr/0077-fsa-config.md), QUESTIONS 37).
- `config set operator-email` (plan U11) is deferred to 2.0.0-beta.1 and refused with exit 2
  `setting_not_available`. `acme-email` and `acme-ca` were added ([ADR 0077](../../adr/0077-fsa-config.md)).
- A reverted config change is exit 5 `rolled_back`, not exit 4 with `reverted: true`
  ([ADR 0078](../../adr/0078-config-safety-and-agent-contract.md)).
- On a stale proxy the URL root keeps the request's scheme, so links from that request are `http://…`
  ([ADR 0079](../../adr/0079-edge-and-runtime-hardening.md)).
- The stack file's app runs `migrate --isolated=75` with an advisory-lock mutex on start. The instance compose file
  still never sets `RUN_MIGRATIONS` ([ADR 0079](../../adr/0079-edge-and-runtime-hardening.md)).
- J2 uses challtestsrv and `FSA_TEST_DNS` instead of §11's CoreDNS, as plan U8 decided
  ([ADR 0075](../../adr/0075-edge-and-domain-mode.md)).
- The E16 measurement (J10) moved from M10 (§12) to U15 in M11. M10 ran no preliminary J10
  ([ADR 0062](../../adr/0062-minimum-hardware.md)).
