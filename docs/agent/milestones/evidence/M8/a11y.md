# M8-T04 Accessibility audit

Target (BUILD_PROMPT §11): WCAG 2.2 AA for the Field App, a keyboard-operable Builder v2. Admin pages and
`/platform` were scanned as well; they are Filament pages and outside the AA target, so Filament-internal
findings there are recorded as accepted exceptions rather than patched in vendor code.

Tooling: `@axe-core/playwright` 4.13.0 with the tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`
(`tests/e2e/support/axe.ts`). Each scan waits for `networkidle`, and on Filament pages for lazy widgets.
Keyboard walkthroughs use `tests/e2e/support/keyboard.ts`. It presses Tab (or Shift+Tab) until the target has
focus. Every focused element must draw an outline or a ring (a box-shadow with no offset and no blur but with a
spread) on itself or on a wrapper up to three levels up. Focus must not leave the page before it reaches the
target; that checks reading order. Finally the helper checks that Tab reaches the end of the page (no trap).
Spec: `tests/e2e/m8-accessibility.spec.ts`. Every test there also runs under the CSP guard (support/test.ts).

## Pages scanned (36 tests, 17 Field App screen states)

| Area | Screens / states |
|---|---|

| Field App, signed in (Pixel 7, one shared session) | home; catalog; fill page 1; page 1 with the error summary; page 2 (repeater row); page 3; page 3 signed; review; detail after submit; submissions; submission detail; notifications; settings; offline home (service worker shell) |
| Admin (owner) | dashboard; forms list; submissions inbox; submission detail; reports explorer; saved reports; workflows; workflow editor; members; SSO; audit log; privacy: retention, legal holds, personal data, my data; API tokens |
| Builders (designer) | canvas builder (v2) with inspector and the sandboxed preview frame; classic builder (v1) |
| /platform (new operator) | login; required MFA set-up page; MFA set-up dialog; organizations; members; health |

Keyboard walkthroughs:
- **Field App fill flow**, keyboard only, from the catalog to a submitted service report.
  - After each navigation, focus lands on the new page's `h1` (RootLayout). On a wizard step it lands on the
    step's `h2` (WizardLayout).
  - Tab order matches reading order: customer, type of job, work done, Next; then description, quantity,
    unit price, Next.
  - The native select works by type-ahead. The acceptance check box works with Space.
  - Confirm signature, Review and Submit work with Enter.
  - No trap.
- **Builder v2**: toolbar → palette (Enter inserts) → inspector (type the label) → Shift+Tab back to the
  selected card, which is the tree's single tab stop.
  - Shift+F10 opens the Move menu with focus on its first item. Esc closes it and returns focus to the card's
    menu button.
  - The handle: Space picks the card up, ↑ moves it, Esc cancels and the live region says so.
  - Visible focus on every stop. No trap.
  - m7-builder-v2 already builds the full §7.2 example with the keyboard only.

## Violations found and fixed

| # | Where | Finding (rule) | Fix |
|---|---|---|---|
| F1 | Admin forms list | `link-name` (serious): rows link to the builder, so an empty "Category" cell rendered an empty link | `->placeholder('—')` on the category column (`FormResource`) |
| F2 | Builder v2 preview | 2.4.7 focus visible: Tab moves focus into the sandboxed preview, and that opaque-origin iframe never matches `:focus`, `:focus-visible` or `:focus-within` in the builder's document, so the CSS outline never showed | `PreviewFeed` marks the iframe `data-builder-preview-focused` while it is the active element (window `blur` / document `focusin`), and `builder.css` draws the outline. Vitest: `preview.test.ts` |

Field App: no axe violations on any of the 17 screen states, and the keyboard walkthrough passed without
app changes. Labels, focus management and the phone layout were built in earlier milestones (horizontal scroll:
LEARNINGS #26).

Verified as false positives (not violations):
- `/platform` MFA set-up dialog, `color-contrast` on the text, the secret and the code inputs. It was measured
  during Filament's opening transition, while the opacity was still rising. Measured after the transition the
  dialog passes. `support/platform.ts` waits for the end of the transition.

## Needs human testing (screen readers, devices)

axe and scripted keyboard checks cannot judge these:
- **Screen readers** (NVDA + Firefox, JAWS + Chrome, VoiceOver iOS Safari, TalkBack Android Chrome):
  - Field App sign-in: email → password → 2FA, and the SSO choice. Errors must be announced.
  - Fill wizard:
    - the step change is announced (focus on the `h2`, "Step 2 of 3");
    - required fields and inline errors are read;
    - the error summary takes focus and its links move to the fields;
    - the repeater table: row headers "Eintrag N", add/remove announcements, and the virtualized list above
      25 rows;
    - calculated totals are announced (`role="status"`);
    - the signature canvas label and the "signed by" state.
  - Review and submit; the offline queue messages and sync results (live regions); the PDF status
    ("being created" → ready → anonymized).
  - Notifications list and unread count; settings (language, larger text, logout dialog).
  - Builder v2: tree semantics (treeitem, aria-selected, expand/collapse), the live-region wording for move,
    insert, delete and undo, the Move menu, inspector field labels, the sandboxed preview frame (reading its
    content).
- **Zoom and text size**: 200% zoom and 400% reflow (1.4.10) on a desktop browser; the Field App's "larger text"
  setting together with OS font scaling on iOS and Android.
- **Real devices**: touch targets and the sticky footer on small phones; the numeric keyboard (`inputmode`) and
  the camera input; Voice Control / Switch Access on the fill flow.
- **Contrast in context**: high-contrast mode (Windows), forced colors (focus rings, badges, status colours), dark
  mode where the OS asks for it.
- **Cognitive**: wording of errors and of the sync and conflict messages in DE and EN.
