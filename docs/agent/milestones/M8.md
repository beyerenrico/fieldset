# M8 Hardening → 1.0: gate report (2026-10-23)

Architecture: ADR 0038 (audit log), 0039 (privacy), 0040 (security hardening), 0041 (`/platform`), 0042
(documentation), 0043 (integration tokens), 0044 (canvas builder default), 0045 (web push deferred), 0046
(performance at 1.0). Parallel agents worked under file ownership; the orchestrator integrated and committed.

## What was built
### Audit log (§8.11, M8-T01)
- Read-only audit log page: filters by actor, event, subject, date and operator; readable entries (labels,
  old → new, local times, secrets hidden); CSV export, queued when large; "History" on forms (both
  builders), submissions, workflows, members and SSO settings.
- One entry per §8.11 action, checked by coverage tests; MFA failures, lockouts, preferences, test mails
  and webhook secret rotation added. Flood caps: lockouts once per IP and window, at most 20 failed
  sign-ins per IP per 10 minutes, then one summary entry.
- `activity_log` is append-only (trigger, no TRUNCATE); pruning (`audit:prune`, 365 days default) and
  sealing only through owner functions. Per-organization SHA-256 hash chain, sealed after commit;
  `audit:verify` (with `--heads` for shipping outside the database); a pruned chain continues from its anchor.
- Entries written during an impersonation carry the operator.

### Privacy (§11 Privacy, M8-T02)
- Per-form retention (delete or anonymize after N months) with legal holds (form or submission); a nightly,
  time-boxed job that re-checks everything under the row lock. Anonymization deletes files and
  notifications, keeps rendition hashes and re-projects `submission_values`; anonymized PDFs answer 410.
- User data export (ZIP of JSON, signed link, 7 days) and erasure (admin or self-service "Delete my
  account"; SSO-only accounts confirm with their email). Erased accounts show as "Deleted user"; platform
  operators and multi-organization members cannot be erased from one organization.

### Security (§11 Security/Operability, M8-T03, T12)
- CSP per surface with nonces, HSTS and Secure cookies behind HTTPS, COOP/CORP, Permissions-Policy, trusted
  proxies and a host allow-list; the builder preview runs on an opaque origin.
- Optional ClamAV upload scanning; JSON logs with secrets redacted and safe messages; optional
  Sentry-compatible reporting without an SDK.
- Admin sessions end after 30 minutes idle or 12 hours (the Field App's 30-day session is unaffected).
- `compose.yaml` publishes the app on loopback only; `.env.production.example` with a test that keeps it safe.
- An OWASP ASVS L2 review by subagents during T03; its findings were fixed in the feature commits.

### Accessibility (§11, M8-T04)
- 36 axe scans (WCAG 2.2 AA) over 17 Field App states, admin pages, both builders and `/platform`;
  keyboard-only walkthroughs; a CSP guard that fails any E2E journey on a policy violation or page error.
  Accepted exceptions and checks that need humans: `evidence/M8/a11y.md`.

### Performance (§11, M8-T05)
- Measured with 100k submissions, 2.3M values and 150k audit entries: `evidence/M8/performance.md`.
- Fixed: saved reports (651 → 365 ms), reviewer inbox (420 → 316 ms), explorer searches (1.7 s → ≤ 291 ms),
  API submission list (268 → 125 ms), Field App repeater evaluation (2.8 s → ≤ 170 ms per keystroke at 4× CPU).
- Accepted exceptions (ADR 0046): classic builder page 1.05 s, Field App first load under Lighthouse
  devtools throttling 3.5 s (slow 4G 2.1 s), 501st repeater row median 203 ms.

### Operator panel `/platform` (§8.12, M8-T06)
- Own login with MFA, organizations list, health (queues, failed jobs, Gotenberg, mail, scheduler, disk),
  time-limited impersonation of an admin member with a reason, banner and exit. Revoking an operator ends
  the impersonation; the API answers 401 `impersonation_ended`.

### Integration tokens (§10, M8-T11)
- Sanctum tokens bound to one organization with abilities per resource on every `/api/v1` route, created
  once-shown, listed and revoked in the admin panel; rate limit per token; audited; pruned daily.

### Documentation and carry-overs (M8-T07, T08)
- `docs/guide/`: install (incl. tamper evidence and a maintenance role), upgrade 0.2 → 1.0, backup and
  restore drill scripts, configuration, admin, Field App, API, troubleshooting (ADR 0042).
- Reviewer detail screen fixed (version endpoint for reviewers); canvas builder is the default (ADR 0044);
  web push deferred (ADR 0045).

## Deviations and known issues
- Performance exceptions (ADR 0046): classic builder page, Field App first load under devtools throttling,
  the 501st repeater row.
- Audit chain uses no secret key; tamper evidence against the database owner needs shipped heads, and the
  default Docker role is a superuser (ADR 0038, install guide).
- Web push deferred (ADR 0045). Screen readers, zoom and real devices need human testers (`evidence/M8/a11y.md`).
- `/horizon` and the API docs are gated by `PLATFORM_ADMIN_EMAILS`, not the operator role.
- Form access, versions and the PDF import report exist only in the classic builder.
- Items for human review: `docs/agent/QUESTIONS.md` (M8 resolved #5, #8 and #10 and added #19–21).
