# R2.1 Rename to Fieldset → 2.1.0: gate report (2026-10-21)

Plan `docs/plans/2026-10-21-001-refactor-rename-to-fieldset-plan.md`, branch `rename-fieldset`. Architecture:
[ADR 0092](../../adr/0092-rename-to-fieldset.md) records the rename, the mapping and the exemptions (plan R6). Units U1–U7
renamed one name family each (PLAN "Rename to Fieldset"); U8 ran this gate. Evidence in [`evidence/R2.1/`](evidence/R2.1/).

**Result: every gate is green; merged to `main` and tagged `rename-done` and `v2.1.0` locally (never pushed).** The first
run was red only in Trivy: CVE-2026-111943 (Go crypto/x509, HIGH, fixed in Go 1.26.10 / 1.27.3), published on the day
of the gate, in every Go binary of the app image and of five of the six third-party images. The human decided "Fix it,
then release" (QUESTIONS 77a); branch `sec-go-x509` rebuilt the app image with fixed Go, moved cloudflared to a fixed
image and gave the four images without a fixed release dated exceptions ([ADR 0093](../../adr/0093-go-x509-fix-for-2-1-0.md)).
Every gate was then run again (see "Rerun after the Go fix").

## What changed
- Product, repository and image `fieldset` / `beyerenrico/fieldset`; CLI `fieldset` (`fieldset:*`, `FIELDSET_*`);
  Docker names and labels `fieldset-…` / `app.fieldset.*`; persisted formats; Fieldset Spec 1.0 with the new `$id`;
  `fieldset/fieldset-php` and `@fieldset/*`; SSO TXT `_fieldset-verification`; dev stack Compose project `fieldset`.
- CHANGELOG 2.1.0 (breaking for any pre-release user, no compatibility). `release:version` takes the version as an
  argument and `release.json` has no version field, so no version file changed (as for 2.0.0); `upgrades_from` is
  `2.1.0-alpha.1` since U5.
- Journeys accept a release evidence folder (`FIELDSET_EVIDENCE_MILESTONE=R2.1`).
