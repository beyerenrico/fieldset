# M0 Foundation — gate report (2026-10-16)

## What was built
- Laravel 13.37 skeleton, Pest 5, Larastan (lvl 8; lvl 10 config for the schema package), Pint, Rector,
  license checks (Composer + npm), coverage thresholds script, GitHub Actions CI (lint → static →
  PHP tests w/ coverage → JS → conformance → E2E → image; audit + licenses).
- Docker: FrankenPHP image (app/queue/scheduler, qpdf), compose with Postgres 16, Valkey, Gotenberg
  (deny private/public IPs, internal network, body limit), Mailpit (dev), health checks.
- Tenancy: hidden-Context `TenantContext` (scoped), throwing `OrganizationScope`, `BelongsToOrganization`,
  `withoutTenant()`, JobProcessing team-id resync, PendingDispatch guard.
- Identity: Organization (Filament tenant, registration/profile pages), memberships, groups, capability
  catalog + six seeded roles per org, Members/Groups/Roles resources with escalation guard, invitations.
- Auth: Filament login/MFA/password reset/email (+change) verification; Fortify headless under `/auth`;
  one shared TOTP secret + recovery codes; deactivated users refused; rate limits.
- API: `/api/v1` envelope, JSON-Pointer validation errors, `X-Organization-Id` middleware, `GET /me`.
- Audit: activitylog with org/actor/IP/UA/request id, redaction, append-only model, explicit events.
- i18n: DE/EN for app strings and framework messages, parity test. `app:install`, DemoSeeder, Horizon gate.

## Gate results
- PHP suite: 190 tests green. PHPStan lvl 8: 0 errors. Pint: clean. Rector: clean.
- Coverage (pcov in `docker/ci` image, `scripts/coverage.sh`): total 90.08 % lines;
  `app/Domain/Identity/Tenancy` 100 % (threshold 95 %).
- E2E (Playwright vs Docker stack): 3/3 green; screenshots in `evidence/M0/`.
- Reviews: two independent reviewer subagents (security/tenancy; correctness/tests/spec). All critical
  and high findings fixed in `93d7328`; see "Review findings" below.

## Review findings and resolution
| Finding | Severity | Resolution |
|---|---|---|
| Admin could self-promote to Owner / demote Owners / grant org.delete | high | `RoleAssignmentGuard`, `ChangeMemberRoles`, `SaveRole`; tests |
| Pre-claimed email + invite → account takeover | high | email-change verification, Fortify profile can't change email, registration off by default, existing accounts must sign in |
| Invitation link = reusable login skipping MFA | high | 410 after use, row lock, no auto-login for existing accounts |
| Queued-job test did not prove ordering | high (test) | job now carries a tenant-scoped relation; handle() queries nothing |
| Duplicate/missing audit entries | medium | membership/role audited explicitly once; groups, permissions, passwords, MFA failures added |
| Tokens revoked across orgs | medium/low | `personal_access_tokens.organization_id`, scoped revocation, middleware check |
| CI never ran E2E | medium | e2e job seeds and runs `npm run e2e` without masking failures |
| Isolation suite partial | low | enumerates every `organization_id` table; allowlist with reasons |
| Recovery code race (Fortify path) | low | `replaceRecoveryCode` re-reads under lock, fails when already used |

## Deviations from BUILD_PROMPT (with ADRs)
- No Filament Shield; capability catalog + custom Role resource (ADR 0017).
- Single 30-day session lifetime for admin and Field App (ADR 0018).
- Recovery codes stored encrypted (Fortify format) rather than hashed (ADR 0016).
- Registration disabled by default (security); journey 1 enables it via env.

## Open questions / known issues (carried forward)
- Filament's MFA challenge failures fire no event, so they are not audited (QUESTIONS #5).
- Group-based submission visibility for reviewers/workers arrives with submissions in M2.
- Audit retention pruning schedule and DB-level append-only trigger: M8.
- User-level deactivation (§9.3 wipe) arrives with devices in M2.
