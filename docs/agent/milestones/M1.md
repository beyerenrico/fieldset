# M1 Schema core + Builder v1 — gate report (2026-10-16)

## What was built
- **Form Schema Spec 1.0** (`spec/form-definition/1.0/`): normative README (structure, 30 element types,
  JsonLogic dialect, decimal/date operators, evaluation algorithm, validation codes, lint rules, versioning,
  checksum, restricted pattern syntax §3.4, limits), JSON Schema 2020-12 meta-schema, role vocabulary.
- **Conformance suite** (`spec/conformance/`): 390 cases (logic 167, evaluate 98, lint 85, meta-schema 35,
  checksum 5), run by both SDKs in CI (`npm run conformance`).
- **SDKs** (MIT): `packages/form-schema-php` (PHPStan level 10, 99.7 % coverage) and
  `packages/form-schema-js` (TS strict, 99.4 % coverage) — meta-schema validation, linter, evaluator, own
  JsonLogic evaluator (ADR 0021), data-contract export, canonical JSON/checksum. Parity fuzzed (~77k inputs,
  0 differences after fixes).
- **Forms domain**: `forms`, `form_versions` (immutable: model guard + DB trigger allowing only retiring),
  `form_access`; actions create/save/publish/rollback/retire/duplicate/archive/import/export/template;
  human diff (elements, pages, settings); three templates (service report, invoice, inspection checklist)
  with lineage (ADR 0023).
- **Builder v1** (Filament): Builder blocks for all 29 types, nested repeater/section/columns, lossless
  mapper with `_source` snapshots (ADR 0022), server-side clone (fresh ids, `_copy` keys, rewritten
  references), key lock after publish, logic editor (rule groups with AND/OR, decimal/boolean-aware
  operators, raw JSON), guided calculation editor, autosave, lint panel, publish (blocked by lint errors),
  version timeline with diff/rollback/retire, access grants, draft export.

## Reviews (three independent reviewer subagents)
| Finding | Severity | Resolution |
|---|---|---|
| Clone kept edited keys/ids churning; cloned containers referenced original keys | P1 | server-side `BlockCloner` + `KeyRewriter` |
| Checkbox/rating defaults saved as strings | P1 | typed default kinds |
| Numbering could not be removed; structural save errors → 500 | P2 | numbering dropped when format empty; Halt + notification |
| Boolean rules never matched; flat AND/OR only | P2 | boolean literals, option `===`, nested rule groups |
| Publish wrote 2+ audit entries; no before/after diff | medium | publish-only entry; checksum + change list |
| Role-name grants stale on rename/delete | low | grants follow renames, removed on delete |
| Diff action unauthorized / no re-auth on hydrate | low | authorize + hydrate check |
| PCRE vs ECMAScript regex divergence, ReDoS, JS precision > 1000 digits, JS RangeError on deep logic, calc-order ties, meta-schema gaps | various | spec §3.4/§5 hardening, 140 new conformance cases, both SDKs updated |
| Livewire dot-path depth 10 broke nested editing | found while testing | `config/livewire.php` overrides |

## Deviations (ADRs)
- Own JsonLogic evaluator instead of json-logic-php/js (ADR 0021).
- `_source` snapshot instead of only `_extra` (ADR 0022).
- Restricted regex subset (spec §3.4) — stricter than "ECMAScript-compatible" for determinism and safety.

## Open questions / known issues
- Repeater evaluation is roughly quadratic (2,000 rows ≈ 2–5 s in the SDKs, reviewer measurement): optimize
  before M6 (500-row target in §11 is met).
- Retiring the current version leaves the form active with no fillable version (catalog will hide it in M2).
- Invoice template rounds tax per line (common practice; per-rate rounding is B4 territory).
- The raw JSON tab shows the saved draft, not unsaved builder state.
