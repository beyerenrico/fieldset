## What was built
### Capture-mode experience (U12, M11-T01)
- fsa renders `FSA_MAIL_CAPTURE=true` for app, queue and scheduler while the instance mailer delivers into the
  catcher. The app reads it as `config('mail.capture')`; unset is false, so checkouts, dev and CI show no banner. The
  stack file keeps it overridable (`${FSA_MAIL_CAPTURE:-true}`).
- Banner (`CaptureModeBanner`, admin panel `BODY_START`, DE/EN):
  - On every page of an organization, for every signed-in member.
  - `full` for organizations on the instance mailer; `narrow` for organizations with their own SMTP (R59): invitations,
    password resets and email address confirmations are captured.
  - Operators see `fsa config set mail smtp --smtp-host <host> --smtp-username <user> --from-address <address>
    --password-stdin`, everyone else "ask your instance owner". Members with `organization.manage` also get the Mail
    settings link, in the full variant only.
  - A named `role="region"`, inline styles, white on `#1e3a8a` (10.4:1), not sticky.
- `MailCheck` warns in capture mode whether or not the catcher answers.
- `fsa config set mail smtp|capture` (`MailApplier`, through ADR 0077/0078's apply, verify and revert):
  - Flags `--smtp-host`, `--smtp-port`, `--smtp-encryption`, `--smtp-username`, `--password-stdin` or
    `--password-file`, `--from-address`, `--from-name`, `--test-to`, `--remove-catcher`. A flag whose name holds a
    secret word is exit 2 `secret_in_argument`.
  - The account lives only in the app roles' env files. It is registered with the redactor first and never journaled
    or written to state, JSON, audit or progress. Apply keeps the previous account in `env/smtp-previous` (0600) for
    a revert.
  - Verify sends a test mail through the socket-less one-off `instance:mail-test` (to `--test-to` or the
    longest-standing operator). A refusal is `test_mail_failed`: exit 5, and capture (or the previous server) stays.
  - Switching to SMTP keeps the catcher (`mail_catcher: kept`) with volume and UI, but binds its SMTP listener to the
    container's loopback, so it receives nothing. `--remove-catcher` drops service and volume; `capture` brings it
    back.
  - After the workers run, `instance:mail-captured` counts pending invitations and unexpired reset tokens
    (`data.mail.captured`, warning `captured_mail`).
- `fsa config set operator-email <email> [--revoke-previous]` (direct key, one transaction in the one-off
  `instance:operator-email`):
  - Refuses an SSO-enforced domain or a deactivated account (exit 2).
  - Creates the account when needed, grants the operator role, and issues a 60-minute owner link when the account has
    no password. The link leaves through the sign-in delivery policy.
  - `--revoke-previous` revokes every other operator and needs `--yes`.
- `fsa config show --catcher-login` hands out the Mailpit password as the one-time secret `catcher_password` in the
  loopback modes. Exit 2 `catcher_login_not_needed` in domain mode, `no_catcher` once removed.
- The launchers' value-flag lists know the new flags. Journey J4.

### Demo data and passwords (U13, M11-T02)
- App side (`App\Domain\Identity\Demo`):
  - `DemoPasswordSource` gives new demo accounts their password. The default stays `password`, so development, tests
    and E2E are unchanged.
  - `RandomDemoPasswords` hands out 24 letters and digits from the CSPRNG.
  - `DemoAccounts` (owner plus eight personas) is the single table that seeding and rotation act on.
- One-offs:
  - `app:demo-seed --passwords=default|random`: one transaction, jobs after commit, audited `instance.demo_seeded`.
    An existing demo changes nothing (`already_seeded`).
  - `app:demo-passwords --check` (read-only): every account with a known password is hashed once against `password`.
    It also returns `organizations {total, non_demo}`.
  - `app:demo-passwords --rotate`: random passwords; sessions, remember-me and Sanctum tokens revoked; one
    `instance.demo_password_rotated` entry per account.
- Reachability (`DemoPasswords::exposure`): `domain_mode`, `proxy_mode`, `local_ca`, `tunnel` (the setting, or a
  tunnel host in `runtime.json`, also an expired one), an unknown `phone_https` value, `runtime_unreadable`. Any reason
  means random passwords.
- Random passwords leave only as secrets `demo_password:<email>` (`secrets` or `--secrets-file`). The public
  `password` is reported as `data.demo.default_password`.
- `fsa install --demo`: phase `demo` (and `demo_rotate`) after `start` and before `smoke`, run again on a resume. A
  repeated install with demo data is `changed: false`.
- `fsa demo [--open] [--rotate-passwords]` works on an installed instance, under lock and journal:
  - seeds, or rotates when the instance is reachable beyond loopback and demo accounts still have `password`;
  - hands out a 15-minute demo owner link under ADR 0070's delivery policy.
- Journey J5 (demo part).

### Phone HTTPS (U14, M11-T03)
- State: the setting `phone_https` (`local-ca` or `tunnel`), local mode only. `lan_address` and `tunnel_subnet` stay
  when the option goes off.
- Local CA (R19):
  - The edge publishes 80/tcp and 443/tcp on the LAN address only, and `https://<LAN address>` becomes the URL. The app
    keeps its loopback port; TRUSTED_PROXIES is the edge's fixed address.
  - Caddyfile (`LocalCaSite`): `tls internal`, `default_sni "<ip>"`, `auto_https disable_redirects`,
    `skip_install_trust`, admin API off. The `http://` site passes only `/phone-trust` and `/phone-trust/*` to the app,
    everything else gets 308 to HTTPS.
  - The LAN address is `--lan-address`, else `LanAddress::best` (first private IPv4 of the launcher's candidates);
    none known is exit 2 `lan_address_required`.
  - A throwaway Caddy container without network copies the public root out of the certificate volume
    (`LocalCaStore`) into `runtime/local-ca-root.crt`. It is accepted only as exactly one CA certificate
    (`LocalCaRoot`).
  - The install smoke test and `config set` verify (`LocalCaEdge`) check HTTPS without SNI against that root, `/up`
    → 308 and the trust page → 200 on port 80.
- Trust page (`PhoneTrustController`, DE/EN), `/phone-trust` and `/phone-trust/root.crt`:
  - 404 unless the runtime says local CA. No session, cookies, CSRF or auth guard.
  - Neither HSTS nor `upgrade-insecure-requests` over plain HTTP (`AllowPlainHttpPage`).
  - The root's SHA-256 fingerprint, iOS and Android steps, the unsynced-data warning, removal steps, a QR code of the
    Field App URL, and a trust check that reveals the Field App link once the phone trusts the CA.
- `fsa config set phone-https local-ca|off` and `lan-address <ip>`. `off` deletes `pki/` and the issued certificates
  after verification. Doctor and status warn `lan_address_changed` with the re-issue command.
- Quick tunnel (R20, R65, KTD12):
  - Compose service `tunnel`: pinned cloudflared as 65532, read-only, every capability dropped, no env, nothing
    published, `restart: "no"`, at a fixed address on its own /28 from 10.215.0.0/16.
  - cloudflared is not a trusted proxy. The runtime pins host and scheme for every request from its address.
  - `fsa tunnel start [--tunnel-admin]`: another account on `password` is exit 3; organizations besides the demo need
    `--yes` (exit 6). Under lock and journal: rotate demo passwords, pull, roll out, read the hostname from
    `/quicktunnel`, write `{hostname, expires_at: +4 h, peer, admin}` to `runtime.json`, verify, start the workers.
    Warnings `tunnel_third_party`, `tunnel_expires`, `url_changed_phone_data`.
  - `renew` sets a new 4-hour expiry. `stop` clears the runtime block, then removes cloudflared and its network.
  - Expiry (AE6): the app answers the expired host with 503 and its public URL falls back to the instance URL.
    `fsa status` reports `expired` without changing anything. The next mutating command (`config set`, `demo`,
    `tunnel`) removes it first (`TunnelSweeper`, warning `tunnel_removed`).
  - `fsa install --phone-https tunnel` installs, then starts the tunnel (`InstallTunnel`).
- R61: tunnel, local CA, domain and proxy refuse each other with exit 2.
- Harness: `FSA_TEST_TUNNEL` (harness images only) swaps cloudflared for a fake built from the pinned Caddy image that
  names a random `fsa-test-….trycloudflare.com`. Journey J6, with Chromium trusting the CA by SPKI.

  `PERF_CA_FILE`, `PERF_THROWAWAY_INSTANCE`). The Playwright project `fsa-instance` serves the instance specs.

  working set peak 1,029 MiB.
- Small budget (MiB): app 384, queue 400, scheduler 208, postgres 160, redis 48, gotenberg 304, mailpit 48,
  edge/tunnel 48, backup 128; 1,728 of 1,728 (2,048 − 320 headroom). One default Horizon worker on `small`, `work_mem`
  floor 4 MB, `medium` scheduler 256.
- Verdicts: install → sign-in link 47.1 s without pulls (met; 838 MB of pulls, 67 s at 100 Mbit/s); queued PDF p95
  3,961 ms (met); API 23/23 under 300 ms (met); admin pages 23/31 under 500 ms (missed, ADR 0083).

### `install --smtp-*` and the full R11 smoke test (gap closed at the gate)
- `fsa install --smtp-host <host> [--smtp-port] [--smtp-encryption] [--smtp-username --password-file|--password-stdin]
  [--from-address] [--from-name]` installs straight into SMTP mode: no Mailpit, no `FSA_MAIL_CAPTURE`, no `/_mail/`.
  The account goes only into the app roles' env files. `SmtpInput` is the one parser for `install` and
  `config set mail`.
- `install.sh` refuses `--password-stdin` without a terminal (exit 2 `password_stdin_unavailable`): its stdin is the
  script.
- A finished instance compares the flags with its state; other values are `use_config_set` naming `fsa config set
  mail`.
- The install `smoke` phase (`InstallSmoke`) adds, each in a socket-less one-off:
  - a one-page PDF through the app's Gotenberg client (`instance:pdf-test`);
  - a test mail to the owner (`instance:mail-test --install`), looked up in Mailpit by Message-ID in capture mode.
  - Failures are exit 4 `pdf_render_failed`, `test_mail_failed` or `test_mail_not_captured`, retryable at `smoke`.
- `config set` verify keeps SmokeTest alone; only `config set mail` sends its own test mail (ADR 0072 amendment).

### Gate fixes
- Tunnel (fix A; ADR 0072, 0078 and 0082 amendments):
  - `fsa tunnel stop` finishes any unfinished tunnel journal and converges, whatever the status says.
  - `tunnel start` checks accounts, target, subnet and image before it rotates demo passwords.
  - Tunnel failures follow `config set`'s contract (exit 5 or 8), and `Interruption` guards `tunnel` and `demo`.
  - A resumed `install --phone-https tunnel` starts the tunnel. `fsa status` reports the tunnel URL as `data.url`.
  - `EvidenceRedactor` masks every `secrets` value.
- Demo and exposure (fix B; ADR 0055 and 0081 amendments):
  - `config set` refuses to widen the reach while any account signs in with `password` (`DefaultPasswordGuard`).
  - `organizations.is_demo` marks the demo, and the slug `demo` is reserved.
  - Rotation also revokes unused sign-in links and reset tokens.
  - Repeats: `operator-email` keeps a usable link; `fsa demo` reports its new link as a change.
- Mail, config safety and Postgres (fix C; ADR 0066, 0069, 0078, 0080, 0082 and 0083 amendments):
  - Every `config set mail` stashes the account in effect; another host drops the stored account.
  - STARTTLS is required, and `--smtp-encryption none` exists for plain relays.
  - Env files keep values with the byte 0x85 or a trailing backslash.
  - A change whose workers already started is completed on resume, never repeated.
  - A failed CA deletion is retried, `lan-address` probes the new address, and R61 hints name their command.
  - Results name `catcher_login_command` in loopback modes.
  - Small Postgres runs `jit=off`, `max_parallel_workers_per_gather=0` and `max_connections=30`.
- Texts and docs (fix D): the trust page's Android advice, the banner's `--from-address` and email confirmations, the
  CHANGELOG entry, `RELEASING.md` checklist items, `install.sh --help`, the U15 ADR amendments, and the local CA key
  location recorded as a deviation.

## Deviations
- `fsa reset` (U23) and the reset part of J5 moved from M11 (§12) to M12: reset needs U16's safety backup and ledger
  (plan U23, PLAN.md).
- The local CA's root and intermediate keys live in Caddy's pki directory on the edge volume `<project>_edge-data`
  (0600 for Caddy's UID), not in `<instance>/certs/` as §10 and §6.3 say. M12 backup and restore must decide whether
  they carry the volume ([ADR 0082](../../adr/0082-phone-https-local-ca-and-tunnel.md), QUESTIONS 44).
- cloudflared is not a trusted proxy, unlike KTD12's "only trusted proxy for the tunnel host": a trusted
  `X-Forwarded-Host` made Symfony answer 400 before the runtime pinned the host. Tunnel clients share its address for
  throttles and audit ([ADR 0082](../../adr/0082-phone-https-local-ca-and-tunnel.md),
  [ADR 0074](../../adr/0074-instance-runtime-state-in-the-app.md) amendment, QUESTIONS 40).
- `fsa demo` works only on an installed instance and has no `--phone-https` (§7 and R30 describe a local install with
  `--phone-https`). A new local demo is `install.sh --demo`; phone HTTPS is `install --phone-https` and `fsa tunnel
  start` ([ADR 0081](../../adr/0081-demo-data-and-passwords.md), [ADR 0055](../../adr/0055-empty-first-data-and-demo-passwords.md)
  amendment).
- `config set domain` and `config set phone-https local-ca` refuse (exit 3) while any account has `password`, whereas
  `fsa tunnel start` rotates the demo accounts itself. R29 says the local-CA edge rotates first
  ([ADR 0081](../../adr/0081-demo-data-and-passwords.md), [ADR 0082](../../adr/0082-phone-https-local-ca-and-tunnel.md),
  QUESTIONS 39, 46).
- STARTTLS is required by default, with or without an account. A relay without TLS needs the new `--smtp-encryption
  none` ([ADR 0080](../../adr/0080-capture-mode-and-mail-config.md), QUESTIONS 45).
- `config set mail smtp` keeps the catcher, receiving nothing, until `--remove-catcher` (R25 says the switch removes
  it; plan KTD13). The way back is `config set mail capture`, not `--capture`. The test mail goes out after apply, with
  the workers stopped, not before ([ADR 0080](../../adr/0080-capture-mode-and-mail-config.md),
  [ADR 0054](../../adr/0054-capture-mail-by-default.md) amendment).
- Mailpit has no read-only UI: the kept catcher's UI can still delete messages
  ([ADR 0080](../../adr/0080-capture-mode-and-mail-config.md)).
- The capture banner shows to every member of an organization, not only to admins (R24, E8)
  ([ADR 0080](../../adr/0080-capture-mode-and-mail-config.md), QUESTIONS 38).
- `config set operator-email --revoke-previous` revokes every other operator: the state does not keep the old address
  ([ADR 0080](../../adr/0080-capture-mode-and-mail-config.md), QUESTIONS 38).
- A changed LAN address is reported (`lan_address_changed`) with `fsa config set lan-address <ip>`; fsa does not
  re-issue on its own as R19 says (plan U14: "offer to re-issue";
  [ADR 0082](../../adr/0082-phone-https-local-ca-and-tunnel.md), [ADR 0057](../../adr/0057-phone-https-local-ca-and-tunnel.md)
  amendment).
- E16's admin-page target (§2.3 "Small") is missed at the 1.0 test volume: 23 of 31 series under 500 ms, misses up to
  1,879 ms. Recorded, not fixed by weakening anything
  ([ADR 0083](../../adr/0083-e16-resource-budget-measurement.md), QUESTIONS 41).
- J10's 2-CPU envelope pins the whole stack to a shared cpuset instead of per-service CPU limits, and runs in a Docker
  Desktop VM, not on a VPS ([ADR 0083](../../adr/0083-e16-resource-budget-measurement.md)).
- `small` runs one default Horizon worker (was 2), and small Postgres runs without JIT and parallel query
  ([ADR 0083](../../adr/0083-e16-resource-budget-measurement.md) and its amendment, QUESTIONS 42, 47).
- The `/platform` link to the catcher (R23) comes with the U20 instance page in M13.

## Open questions
- 38: The capture banner shows to every member, not only admins. `--revoke-previous` revokes every other operator.
- 39: `config set phone-https local-ca` refuses while demo accounts have `password`; `fsa tunnel start` rotates them.
  A failed local-CA turn-on leaves its CA on the volume.
- 40: cloudflared is not a trusted proxy: tunnel clients share its address for throttles and audit. What real
  cloudflared forwards is unverified.
- 41: E16 admin-page targets are missed at 100k submissions on 2 GB / 2 CPUs. Options: document the data size that
  needs 4 GB, ADR 0046's query follow-ups, more memory for Postgres, or a larger E16. Should the M13 gate enforce
  timings?
- 42: `small` runs one default Horizon worker. Margins are about 30 MiB per slot; the backup and tunnel slots,
  `medium` and `large` are unmeasured, and the 320 MiB headroom is an estimate.
- 43: A resumed SMTP install whose test mail was refused can retry but not change server or account. Every resumed
  smoke phase sends another test mail. `mail.catcher: removed` also means "never created".
- 44: The local CA keys live on the edge volume, not in `<instance>/certs/`; M12 backup and restore must include it,
  or phones trust a new CA after a restore.
- 45: STARTTLS is required by default; plain relays need `--smtp-encryption none`. Another host drops the stored
  account.
- 46: `config set domain` and the local CA refuse while any account has `password`. An operator created by
  `config set operator-email` has no organization, so `fsa login-link` refuses them. On a legacy database the demo
  may get `demo-2`.
- 47: Small Postgres runs `jit=off`, no parallel workers, 30 connections; the speed effect is unmeasured until the
  gate's J10. `operator-email` has no `Interruption` guard; a renew killed outright resumes only through
  `fsa tunnel renew`; a CA-deletion retry runs the full rollout.
- 22: Phone HTTPS is demo-grade; whether Android trusts a user-installed CA for PWAs is unverified.
- 25: The first public GHCR publish is irreversible, and the signer identity is built into every release.
- 26: Backups stay on the instance's host; the encrypted-backup key is handed over once.
- 27: Confirm the Trivy exception policy for third-party images (expiry 2026-11-17, postgres 2027-01-16).
- 29: A resumed install after `app_install` issues a 15-minute admin link, not the 60-minute owner link.
- 30: `fsa uninstall` leaves the empty instance directory.
- 31: `--orphans` has no second confirmation beyond `--yes`.
- 32: The uninstall final backup runs while app, queue and scheduler keep writing.
- 33: The owner digests need APP_PREVIOUS_KEYS kept on a future APP_KEY rotation.
- 34: Document links and admin links in jobs started during a tunnel point to the tunnel host, which does not serve
  them.
- 35: Unverified: caddy-docker-proxy labels, Portainer/Coolify import of the stack file, Traefik's per-router
  `certresolver`.
- 36: No ZeroSSL fallback in domain mode. The production shim passes `FSA_TEST_DNS`, and `nosniff` is sent twice.
- 37: `--yes` is needed on every URL change. (`operator-email` landed in U12.)
- Superseded: 24 (the hardware floor was a target until J10) by ADR 0083 and QUESTIONS 41. Resolved earlier: 23 and
  28 (ADR 0065/0071).
