# M4 Workflows + notifications → MVP 0.1.0 — gate report (2026-10-17)

## What was built
- **Workflow engine** (ADR 0032): trigger + JsonLogic conditions + ordered steps; one run per
  (workflow, submission, event id) with a definition snapshot; queued steps with backoff, pause/resume,
  retry-safe side effects (mail ids, notify markers, webhook in-flight markers); visible failures (run
  and step status, audit, admin notification) with manual retry from the failed step; workflow starts
  run in a queued, retried job and a sweep restarts unprocessed events and stalled runs.
- **Triggers**: submitted, status changed (to), approved, rejected, form published, schedule (cron in the
  organization time zone), manual (inbox button, double-click safe).
- **Steps**: send_email (fixed / field value or role / submitter / group; template tokens; PDF
  attachment or link; per-submission and per-organization caps), notify (users, groups, roles;
  channels), set_status (completed or void only), generate_document (chosen design), webhook (HMAC-SHA256
  + timestamp, exponential retries, SSRF guard with IP pinning, port allow-list, masked URLs, capped
  responses), request_review.
- **Review tasks**: group or user assignee, SLA due date + one overdue reminder, approve resumes the run,
  "request changes" sets changes_requested with the comment and notifies the submitter, resubmit starts a
  new run (number kept), tasks cancelled when the submission leaves review another way.
- **Lifecycle** (§6.5): submitted → completed when no workflow reviews; approved → completed after the
  remaining steps and approval-triggered runs.
- **Notifications** (§8.9): queued in-app (admin bell, Field App centre) and branded mail per user, event
  and channel preferences; review assigned, changes requested, approved, workflow failed, form available,
  workflow notices; inbox limited to active memberships.
- **Admin**: Workflow resource (steps Builder, validated conditions and cron), runs timeline with retry,
  My tasks, inbox approve / request changes / run workflow, webhook endpoints (secret shown once),
  notification preferences.
- **API**: `GET /tasks`, `POST /tasks/{id}/complete`, `review` + `open_task_id` + per-user `can_edit` on
  submissions, manifest tasks, notifications and preferences endpoints (contract updated).
- **Field App**: open tasks, review panel, changes-requested banner + resubmit, notification centre with
  organization-aware links, preferences.
- **Demo**: "Prüfen und an Kunden senden" workflow and a disabled webhook example.

## Reviews (security, backend correctness, UX/a11y — no critical or high findings)
| Finding | Severity | Resolution |
|---|---|---|
| Assignment granted permanent visibility (Designer could read submissions) | medium | open tasks only, requires view_assigned (47fcef4) |
| Notification inbox showed orgs the user left | medium | filtered to active memberships (API + bell) |
| Field-derived mail recipients uncapped | medium | per-submission/org caps, definition size limits |
| set_status could strand submissions/tasks/runs | medium | completed/void only; leaving review cancels tasks + runs |
| Review notices to group members who cannot act | medium | recipients filtered by submissions.review |
| Failed workflow start silent | medium | queued retried start job + sweep |
| Several review workflows / approval-triggered runs | medium | one review workflow per scope; post-approval semantics |
| Reviewers offered edit/resubmit of others' submissions | high (UX) | per-user can_edit, Home drafts own only |
| notify/webhook duplicates on retry; decision after failed run → 500 | low | markers; 409 review_blocked/task_closed |
| UTC times, raw labels, contrast, wording, flaky tests | low | fixed |

Found by the E2E runs: the builder left new element keys empty so publishing failed behind the dialog
(c77f83b), the version history did not refresh after publishing (609c00c), and the canonical render
input hashed the workflow status so re-renders after review changed `input_hash` (153880d, renderer 1.2.0).

## Deviations and known issues
- Optional daily digest (§8.9) not built.
- Task decider keeps visibility of the decided submission (needed for the Field App refetch).
- Manual workflows can be run by reviewers (documented in ADR 0032).
- Webhooks are at-least-once; a POST with an unknown outcome is not repeated automatically.
- Notifications keep the language they were rendered in.
