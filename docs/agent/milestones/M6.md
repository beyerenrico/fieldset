# M6 Offline-first: gate report (2026-10-18)

## What was built
- **Offline store** (ADR 0035): Dexie 4.4.6 database `fsa-offline` (drafts, outbox, attachments, forms, form versions, meta).
  - Every row is scoped by organization and user.
  - It replaces the M2 key-value store, and the device record is migrated.
- **Local-first autosave**: every edit is written to the device (300 ms debounce, 2 s at most) and flushed on pagehide, freeze and hide.
  - A restored draft starts as "Saved on this device".
  - One tab edits a draft at a time (Web Lock); other tabs open it read-only.
- **Outbox and sync engine**:
  - Ordered ops per submission: create → uploads → update → submit → send.
  - Persisted idempotency keys and bodies; backoff with Retry-After.
  - Triggers: app start, `online`, visible, enqueue, "Sync now", login, a 60 s interval, and a Background Sync wake-up on Chromium.
  - Single flight across tabs; ops are sent only under the session of the user who owns them.
  - Lost answers are adopted (PUT, create, submit). Conflicts offer "keep mine" or "use office version". Blocked submissions explain the next step.
- **Attachments**: compressed once by the renderer, stored as bytes, uploaded by the engine, pruned after submit.
- **Catalog cache**: incremental `/sync/manifest?since=`.
  - Unknown fillable forms are fetched; revoked forms are purged; retired versions are marked.
  - The cache is kept per organization and records its user.
- **PWA shell**: vite-plugin-pwa 2.0.0 / Workbox 7.4.1 service worker, scope `/app/`.
  - The shell is precached as `/app/shell`, so it is served with the CSP.
  - The preview build has no service worker.
  - Update banner flushes drafts; install prompts for Chromium and iOS; at most one banner at a time.
- **Offline start**: the app starts from the cached session.
  - A remembered reauth or a pending server logout blocks it.
  - A lie-fi indicator shows when the server is unreachable.
- **Logout and wipe**:
  - A warning shows the number of unsynced submissions.
  - Every tab is told before the purge.
  - IndexedDB, Cache Storage, the service worker and `fsa.*` keys are cleared; settings stay.
  - The server logout is retried until it succeeds.
- **Backend**:
  - Deactivating a member's last active membership ends their sessions and requests a device wipe. Revoking a device ends the user's sessions and remember-me token.
  - Customer send is idempotent by key on `document_sends`.
  - Submit accepts `client_submitted_at`, shown in the admin view.
  - The manifest returns `retired_version_ids`.
  - The SPA shell files always go through Laravel (CSP).
- **Settings**: unsynced counts matching the header, "Sync now", storage usage with a near-full warning, persistence request.

## Reviews (security, correctness, UX/a11y): no critical findings
| Finding | Severity | Resolution |
|---|---|---|
| A tab left from a lost session could send user A's outbox under user B's session | high | engine checks the session owner per run and per submission; op ids include the user; writes check the session |
| Offline/failed logout left the server session and remember-me cookie valid | high | `fsa.pendingLogout` blocks `/me` until the server logout succeeds |
| Edits written between draft PUT and submit were marked synced and lost | high | edits are sent before submit; only the covered version is marked synced |
| changes_requested on a retired version was pre-blocked (server accepts it) | high | pre-block only for drafts |
| A refused queued submit silently went back to draft; blocked + queued was a dead end | high (UX) | decisions surface on detail and lists with a link to the form |
| Restored draft said "No changes yet"; storage-full blamed the connection | high (UX) | starts as saved; typed storage-full message, announced once |
| Revoked device kept syncing after a remember-me login | medium | revoke ends sessions and the recaller token |
| Offline restart bypassed reauth | medium | `meta.session.reauth` |
| False conflicts / duplicate offers after lost answers | medium | recorded saves adopted; own submit recognized |
| Send replaced in flight was dropped; blocked uploads stuck; rejected runs broke follow-ups | medium | key-checked op updates; `attachment_blocked`; run errors recorded |
| Focus stealing, offline shown as error, raw error texts, banner stacking, copy | medium/low (UX) | fixed (regions, focus rules, localized reasons, one banner, formal German) |
| Lost-org rows kept, catalog served to the next user, client_submitted_at overflow, op id collisions | low | purged on fresh `/me`; catalog per user; lower bound; namespaced ids |

Found by the E2E runs:
- The renderer's deferred focus after "add row" pulled focus back while the user typed, so input landed in the wrong field. It existed since M2 (3f38652).
- A new draft could not be opened offline (a371724).
- The Fortify login limit (5/min per email) was hit by the added journeys; a third demo worker spreads the logins.

## Deviations and known issues
- Background Sync only wakes open tabs (QUESTIONS #13).
- Server time decides number and period (#14).
- Shared devices keep other users' unsynced rows hidden (#15).
- A wipe persists after reactivation (#16).
- Revoking a device signs the user out everywhere (#9).
- A device that never comes back online keeps its server session until it expires.
- The pending badge's 10 s delay is counted per tab.
- `useDraftEditor` is over the 50-line function guideline.
- The builder page is heavy, so E2E waits up to 30 s for its navigation and publish (#8).
