Architecture: ADRs 0047–0064 record the v2 decisions E1–E18: 0047 (version 2.0.0), 0048 (the image is the
installer), 0049 (`fsa`), 0050 (GHCR and GitHub Releases), 0051 (amd64 and arm64), 0052 (Caddy edge), 0053
(modes), 0054 (capture mail), 0055 (first data, demo passwords), 0056 (owner sign-in link), 0057 (phone HTTPS),
0058 (health-gated upgrades), 0059 (encrypted backups), 0060 (signed images, manifest), 0061 (update check off),
0062 (minimum hardware), 0063 (image size budget), 0064 (local harness, human publish). As built in M9: 0065
(image binaries and size), 0066 (`fsa` architecture), 0067 (release pipeline and harness), 0068 (Horizon, sign-in
links), 0069 (compose renderer, resource budget), 0070 (install.sh and shim), 0071 (binaries from source, scan

## What was built
### Bootstrap (M9-T01)
- BUILD_PROMPT_V2 and the plan committed; AGENTS.md points at both; M9–M13 in PLAN.md; ADRs 0047–0064;
  risky defaults logged as QUESTIONS 22–26.

### Image (U1, M9-T02)
- One image runs every role: app, queue, scheduler and the `fsa` ops container (the backup daemon entry point is
  in place for U16). The entrypoint skips `optimize` and migrations for `fsa` and the backup daemon.
- Uncompressed size 2.12 GB → 507 MB (arm64) / 497 MB (amd64): allow-list `.dockerignore`, Composer only in a
  build stage, flattened base with the toolchain purged.
- Ops binaries: Docker CLI 29.9.1 (static release, SHA-256 per architecture), Compose 5.6.0 and age 1.3.2 with
  `age-plugin-batchpass` cross-compiled from verified release tags with Go 1.27.2, PGDG `postgresql-client-16`.
  No cosign in the image. `docker/app/binaries.json` feeds the license check.
- No permission errors in the start-up logs (R6). OCI labels and `config('app.version')` come from
  `APP_VERSION`/`APP_REVISION`. Every base image is pinned by multi-arch index digest.

### Instance domain core (U2, M9-T03)
- `app/Domain/Instance`: `DockerGateway` (docker CLI through Symfony Process, no shell, env values by name), a
  marked instance directory with atomic, symlink-safe writes, a versioned `InstanceState` without secrets,
  per-service 0600 env files, `InstanceLock` (holder container ID and start time), `OperationJournal` (a phase is
  written before it runs) and `Supervisor` (resume, takeover, detached supervisor container).
- One result envelope (`schema_version`, `command`, `status`, `changed`, `data`, `secrets`, `warnings`, `errors`),
  NDJSON progress with `--json`, `--secrets-file`, secret flag values refused (exit 2), confirmations exit 6
  without a TTY. Exit codes 0–10: 1 internal error, 8 rollback failed, 9 aborted before any change.
- Arch test: the runtime code and everything outside the instance domain stay off the ops namespaces.

### Compose renderer and resource budget (U3, M9-T04)
- Each instance gets a generated compose project `fsa-<slug>-<hex>`. Every container, volume and network carries
  the instance UUID label, and every service gets a memory limit from `ResourceBudget` (small: 1728 of 1728 MiB,
  worst case). Logs are capped. A guard refuses a socket mount, `RUN_MIGRATIONS` and `$` interpolation.
- Local mode with capture mail: app, queue and scheduler send to Mailpit (UI on loopback, SMTP never published).
  Valkey runs with a password. Horizon, FrankenPHP, Postgres and Gotenberg are sized from the budget. A read-only
  runtime directory (`runtime.json`) carries URL and gate. Every state value passes a strict input grammar.

### Sign-in links, `app:install`, Horizon (U6, M9-T05)
- `app:install --owner-link | --password-file | --json` creates the first organization and owner and grants the
  operator role. The owner link (60 minutes) uses the password-reset broker. `--password` is deprecated.
- `fsa login-link <email>`: a 15-minute single-use link for an existing admin, stored hashed and rate-limited. A
  newer link invalidates older ones. The token travels in the URL fragment and the landing page POSTs it. MFA is
  still required, and the link never creates a `/platform` session.
  - The landing page has states for valid, used, expired, rate-limited, invalid and SSO-required, in DE and EN.
  - Issuing is audited with actor "cli" and the host UID. `fsa status` lists unused links; they are pruned 30
    days after expiry.
- Horizon opens only for an operator with a `/platform` session.

### Release pipeline and harness (U7, M9-T06)
- `release.yml` on `v*` tags builds both architectures with SBOM and provenance and pushes by digest. It signs
  images, manifest and install.sh keylessly, in a `sign` job that runs no PHP or Composer. The Trivy scan runs
  before tagging; then a draft release, a logged-out pull of every digest and the finalize step. Actions and
  linter images are pinned.
- `release:manifest` and `release:version`, `distribution/manifest.schema.json`, and `distribution/release.json`
  with six third-party pins by index digest.
- Local harness: `registry:3`, a static release server and a per-run cosign key. Journeys run as the `Install`
  Pest suite, outside the default run. CI gained shellcheck, hadolint, actionlint, image-scan and
  install-journeys. First `RELEASING.md`, including the pre-release one-liner.

### install.sh and shim (U4, M9-T07)
- `install.sh` is POSIX and safe against truncated downloads. It verifies the signed manifest with the pinned
  cosign image against the identity built into it, before it pulls anything else. Then it pulls the app image
  by digest, creates the instance directory (0700, marker), copies the shim from the image and hands over to
  `fsa install`. Only a harness build accepts a test key or plain HTTP.
- The shim `<dir>/fsa` reads the ops image digest from the state. It runs the ops container with host facts, a
  user per Docker runtime, a nonce check for path sharing, parent mounts for file flags and a private tmpfs
  HOME, and refuses reserved paths. The sign-in link reaches the browser through a 0600 hand-over file.
  `DOCKER_DEFAULT_PLATFORM` is passed through.

### Lifecycle commands (U5, M9-T08)
- `fsa install` (local mode) runs journaled phases: doctor → secrets → state → pull → up → migrate →
  app_install → start → smoke → done. A failed install resumes with its first secrets. A re-run with the same
  flags reports `changed: false` and makes no Docker call. The app port is 8080 or the next free one up to 8099.
  A foreign project with the same name is exit 7, and orphans are named. `--domain` runs the DNS preflight, then
  stops.
- `fsa doctor` checks Docker, architecture, memory, disk, path sharing, permissions, stale files, DNS, registry,
  clock and ports, plus services with `--post`. `fsa status` is read-only. `fsa logs` redacts secrets.
  `fsa version` needs no instance.
- `fsa uninstall` removes labelled resources only. `--keep-backups` writes a final backup first, and
  `--orphans` is guarded. `fsa login-link` issues admin links.
- The sign-in link goes to `--secrets-file`; to the browser only with `--open` or for a person at a desktop
  terminal; otherwise under `secrets`.

### Gate fixes
- Launchers: private tmpfs HOME/DOCKER_CONFIG; reserved paths refused in the shim, install.sh and `LaunchGuard`;
  leading flags; a terminal only for a person; NDJSON-only stderr with `--json`; error codes aligned with `fsa`.
  The image's `fsa` wrapper finds the command after leading flags and refuses unknown ones.
- Uninstall: final backup, orphan guards, refusal for an unknown installation ID, partial uninstall exit 4.
- Release: signing split from the manifest job; base images pinned by digest.
- `DOCKER_DEFAULT_PLATFORM` end to end: cosign runs as the engine's platform, doctor reports emulation, and memory
  limits double under emulation. With that, J1 and J12 run under amd64 emulation. The AE3 check ignores
  healthcheck exec events.
- Tests: Livewire's per-request state is flushed between test requests; the clock dataset is evaluated lazily;
  the coverage run gets 2 GB.
- Docs: pre-release one-liner, harness cleanup and linter commands, amended ADRs.

## Review
Five reviewer subagents: correctness, security, data safety, agent operability and docs accuracy. The table lists the
high findings; the Area column is inferred from the fix commits.

| Finding | Severity | Area | Resolution |
|---|---|---|---|
| The image's `fsa` wrapper took a leading flag for the command: `fsa --json status` ran `artisan list`. Unknown commands reached `artisan fsa:<x>` (plain text, exit 1) | high | agent operability | The first non-flag argument is the command. An unknown one exits 2 `unknown_command` with the command list, which is checked against the registered commands (be7a205) |
| `fsa uninstall --orphans <uuid>` force-removed any installation's resources, even a live or moved one | high | data safety | Accepts only an orphan that install reported for this directory. Exit 7 `orphans_live` while one of its containers runs; volumes of an installation used elsewhere are kept (473b9c7, ADR 0073) |
| A file flag into `/tmp` mounted the host's shared `/tmp` over HOME/DOCKER_CONFIG of the socket-holding container, so another local user could plant a CLI plugin | high | security | Private tmpfs `/run/fsa-home`. Reserved system and shared paths are exit 2 `path_reserved` in the shim, install.sh and `LaunchGuard`, with a parity test (c5ea471, 48df00b) |
| `RELEASING.md`'s harness cleanup command failed without `FSA_HARNESS_DIST` | high | docs accuracy | The command sets an absolute `FSA_HARNESS_DIST` (f7544dc) |

The repository records no per-finding severity for the rest. These medium and low findings were fixed:
- **Exit codes and envelope (473b9c7):**
  - Missing install input is exit 2, not 6.
  - A partial uninstall and a one-off without output are exit 4, not 1.
  - Failure envelopes carry `changed`. The supervisor catches any exception: exit 9 before a change, 1 after.
  - Invalid UTF-8 in logs no longer breaks the JSON document.
  - The doctor no longer reports the instance's own ports as taken. A lock heartbeat is written around every
    phase.
  - Every end-anchored pattern uses the PCRE `D` modifier: before, `"host\n"` passed.
- **Links and personal data (473b9c7):**
  - A sign-in link goes to the browser only with `--open` or for a person at a desktop terminal.
  - A used owner link retires its broker token. Login links are pruned.
  - The owner's e-mail and name are HMAC digests in the state history and archived journals; the journal
    history keeps 20.
- **Uninstall data safety (473b9c7, ADR 0073):**
  - `--keep-backups` deleted the only APP_KEY. It now writes a final dump, storage archive and APP_KEY first.
  - An unknown installation ID refuses (exit 7) instead of deleting the keys while volumes remain.
- **Launchers and release (d7d687a merge):**
  - A terminal only for a person, and NDJSON-only stderr with `--json`; shell errors are kept off stderr.
  - Error codes aligned with `fsa`; install.sh honours `--yes`.
  - Signing moved to a job without PHP or Composer. Base images are pinned by digest.
- **Docs and ADRs (f7544dc, e90b27b, ed0159a):**
  - Configuration guide: `FRANKENPHP_CONFIG`, `HORIZON_*`. Install guide: `--password-file` inside the
    container.
  - `RELEASING.md` gained the `verify-blob` trigger flag. PLAN wording fixed.
  - Amendments to ADRs 0048, 0049, 0051, 0055, 0056, 0063, 0065–0067 and 0070–0072, plus 0062 (f82ad38).
- **Found by the gate runs:**
  - Livewire's per-request static injected a script into later tests' `/login-link` page; tests now flush it
    (ed0159a).
  - A time-based Pest dataset was evaluated at file load, and the coverage run needed 2 GB (1c42ab7).
  - J12 counted healthcheck exec events as changes. amd64 Mailpit was OOM-killed under emulation, so limits are
    doubled there (f82ad38).

## Deviations
- The Compose file is JSON inside `compose.yaml`, because `symfony/yaml` is not a dependency
  ([ADR 0069](../../adr/0069-compose-renderer-and-resource-budget.md)).
- Valkey gets a password and a labelled volume; 1.0 had neither
  ([ADR 0069](../../adr/0069-compose-renderer-and-resource-budget.md)).
- cosign was dropped from the image: `fsa` verifies with the pinned cosign image. Compose and age are built from
  source instead of release binaries ([ADR 0071](../../adr/0071-image-binaries-from-source-and-scan-policy.md),
  [ADR 0070](../../adr/0070-install-script-and-shim.md)).
- Third-party images carry dated, scoped Trivy exceptions instead of zero fixable findings. QUESTIONS 27 is
  still open ([ADR 0071](../../adr/0071-image-binaries-from-source-and-scan-policy.md)).
- The release tooling commands are `release:manifest` and `release:version`, not `fsa:*`
  ([ADR 0067](../../adr/0067-release-pipeline-and-harness.md)).
- Exit code 1 is added for internal errors ([ADR 0066](../../adr/0066-fsa-command-architecture.md)).
- `fsa uninstall --keep-backups` writes a final backup first ([ADR 0073](../../adr/0073-uninstall-final-backup.md)).
- Memory limits are doubled under emulation ([ADR 0062](../../adr/0062-minimum-hardware.md),
  [ADR 0070](../../adr/0070-install-script-and-shim.md)).
- The E16 measurement moved from M10 (§12) to U15 in M11 (J10). `fsa reset` moved from M11 to M12 (U23), as the
  plan decided.
- `fsa install --domain` runs the DNS preflight, then stops with exit 2 `unsupported_mode` until U8
  ([ADR 0072](../../adr/0072-fsa-lifecycle-commands.md)).
- The R11 smoke test has no PDF render or test mail until U12 ([ADR 0072](../../adr/0072-fsa-lifecycle-commands.md)).
- `fsa install --owner-password-file` (R27) is not built yet
  ([ADR 0056](../../adr/0056-one-time-owner-sign-in-link.md)).
- Install phase order: the operator grant is inside `app_install`, and the stack starts in two steps
  ([ADR 0072](../../adr/0072-fsa-lifecycle-commands.md)).
- Missing install input is exit 2, not the plan's 6. The browser hand-over uses a file instead of `open_url`
  ([ADR 0070](../../adr/0070-install-script-and-shim.md), [ADR 0072](../../adr/0072-fsa-lifecycle-commands.md)).
