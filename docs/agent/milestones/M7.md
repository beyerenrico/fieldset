# M7 SSO + Builder v2: gate report (2026-10-18)

Architecture: ADR 0036 (SSO) and ADR 0037 (Builder v2), both with amendments. The parallel-agent ownership notes from this milestone are in git history (`git log -- docs/agent/milestones/M7.md`).

## What was built
### SSO (§8.7)
- **Data model:** per-organization identity providers (OIDC or SAML) with encrypted config and a write-only secret; DNS-verified domains that only one organization can verify; claim mappings (role XOR group, never Owner); external identities keyed by provider + subject.
- **OIDC:** socialiteproviders/openidconnect 1.0.1, covering Entra (tenant and `tid`), Google Workspace (`hd` + email_verified) and generic OIDC (Keycloak, Authentik, Zitadel).
  - id_token checks: issuer, audience, signature (JWKS), nonce and PKCE S256.
  - A Google or Microsoft issuer requires its flavor.
  - HTTP goes through an SSRF-guarded client with address pinning.
- **SAML 2.0:** socialiteproviders/saml2 4.10 plus our own hardening (Audience, Recipient, Destination, InResponseTo, replay after signature, XXE).
  - The ACS runs without a session and hands over through a one-time ticket.
  - The subject is a persistent NameID or a configured stable attribute.
- **Home-realm discovery:** email-first login in the admin panel and the Field App, throttled per address and IP. Enforced domains go straight to the IdP; others choose between the IdP and a password.
- **JIT and mapping:** membership with a default role and group; IdP-managed roles and groups re-synced on every login; deactivated users and memberships refused; cross-organization invitations work under enforcement.
- **Enforcement:**
  - Password login and reset are refused for enforced domains on Fortify, Filament and invitation paths.
  - A break-glass Owner keeps password + MFA, and responses for enforced addresses are uniform.
  - Switching enforcement on ends password sessions.
  - Managed email addresses cannot leave the domain.
- **Administration:** an Owner-gated SSO page with copyable URLs, TXT instructions, a test sign-in with its result, translated last errors, the enforcement preconditions and a confirmation step.
  - Connection changes unlink identities and alert the Owners.
  - Daily domain recheck and hourly provider check; `sso_misconfigured` notifications, throttled.
  - Login CSRF protection through session-bound start tokens.
  - Production refuses the dev-only settings.
- **Keycloak 26.7.5** in compose (profile `sso`, also in CI), with a realm containing OIDC and SAML clients, a groups mapper and a user-id mapper. A demo seed provides orgs `sso-demo` (OIDC, enforced) and `saml-demo` (SAML).

### Builder v2 (§8.2)
- **Canvas page:** a page next to the classic builder that edits the same draft, so no migration.
  - The browser holds the working copy (TypeScript store with pure operations, 100-step undo/redo); the server validates whole definitions (`SyncDraft`) with a checksum guard against stale tabs, in both builders.
  - Page HTML is 82.7 kB, against 4.5 MB for v1; JS is 34 kB gzipped.
- **Interaction:**
  - Palette, canvas and inspector. The canvas is a keyed DOM renderer under `wire:ignore`, with our own SortableJS 1.15.7 import.
  - Full keyboard model: pick up, move, into or out of groups, between pages, Move menu with Shift+F10, add/remove columns, "Go to properties". A live region announces changes.
  - The inspector reuses the v1 fields (logic and calculation editors). Server key suggestions never overwrite a typed key.
- **Server operations:** publish, Preview PDF and export are guarded by the draft checksum, and publish re-reads the draft under its lock. Explicit saves are audited.
- **Cloning:** fresh ids, unique keys and rewritten references (this also fixed v1's duplicate `_copy` keys).

Found by the E2E runs:
- The admin login's password step kept the email step's buttons.
- libcurl maps `*.localhost` to loopback, so the containers could not reach Keycloak until the address was pinned (LEARNINGS #58).
- Discovery throttling locked out logins behind one IP (now 10/min per address).

## Deviations and known issues
- One IdP per organization. No RP-initiated logout or SAML SLO.
- Break-glass use is audited but not notified.
- A pasted SAML metadata certificate rotation no longer notifies (a metadata URL heals itself).
- On the SSO settings page, pressing Enter in the enforcement form submits without the confirmation dialog; the button path confirms.
- The reviewer's Field App detail screen showed a generic error panel after approving in an E2E leftover page. To be investigated in M8.
- Builder v2: v1 stays the default. Screen-reader behaviour of the tree pattern is unverified with real screen readers (M8 a11y audit). Undo history is not persisted.
- iOS standalone PWA leaving its scope for the IdP is untested (QUESTIONS #18).
