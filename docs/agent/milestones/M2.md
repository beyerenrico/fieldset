# M2 Field App online — gate report (2026-10-16)

## What was built
- **Submission API** (`/api/v1`, contract `docs/api/field-app-v1.md`, OpenAPI 3.1 at `/docs/api` for
  platform admins and member managers): forms catalog, version fetch, sync manifest, draft upsert with
  client UUIDs and revisions (409 with the server copy), attachments (client UUIDs, content sniffing,
  allow-list, GD re-encode without EXIF, pixel limit, private disk, sandboxed downloads), submit with
  `Idempotency-Key`, server re-evaluation via form-schema-php, attachment manifest, retired-version and
  revoked-access checks, gap-free numbering per form and period (org time zone).
- **Domain**: `submissions`, `submission_events`, `attachments`, `number_sequences`, `idempotency_keys`,
  `devices`, `submission_values` read model + `app:reproject`; in-house status machine (ADR 0025);
  FormAccessResolver (Owner/Admin all, else role/group grants); visibility own + group `share_submissions`.
- **Devices** (§9.3): registration with a one-time secret (hash stored), `POST /api/v1/auth/device-status`
  ok/reauth/wipe, revoke + remote wipe from the member page, sessions bound to a device end when it is
  revoked, deactivating a user revokes tokens, sessions and devices.
- **Retry safety** (ADR 0027): request-wide idempotency transaction with an advisory lock, 2xx-only
  replay, natural idempotency of submit and draft saves, allocator that never re-issues a number.
- **Renderer** `packages/form-schema-react` (MIT): all spec 1.0 element types, live `evaluate()`,
  `requiredIf`/`readOnlyIf` from the JS SDK's new presentation maps, wizard/scroll, pointer errors with a
  focusable summary, repeater cards/table with virtualization and stable row keys, signature_pad, photo
  compression, opt-in location, sanitized Markdown, Intl formatting, DE/EN messages.
- **Field App** `resources/field-app` (served at `/app/`): login + 2FA, device registration and
  device-status handling, org picker, home (drafts, favourites, recent), catalog, fill with server
  autosave and conflict choice, review & sign, idempotent submit, my submissions, detail, settings,
  DE/EN, per-route titles and focus.
- **Builder preview**: `/form-preview/` entry in a phone/tablet iframe, unsaved definition via
  origin- and source-checked postMessage, strict CSP.
- **Fillable-PDF import** (§8.13, ADR 0024): qpdf JSON parser job, mapping, repeater detection,
  `x-import` metadata, import report in the builder, limits; generated fixtures (pdf-lib).

## Reviews (three reviewer subagents: security/tenancy, backend correctness, frontend races/a11y)
| Finding | Severity | Resolution |
|---|---|---|
| Device revoke left its session usable | high | session bound at registration, `EndRevokedDeviceSession` on web/api/admin (0925fa3) |
| Idempotency replayed state-dependent 4xx; not atomic with submit | high | 2xx-only, advisory-locked request transaction, natural idempotency (f6f8ccf, ADR 0027) |
| Reset/format change between versions → duplicate number → every submit 500 | high | allocator skips issued numbers under a per-form lock |
| Uploads not awaited before review/submit; stale draft cache on reopen | high | shared draft session, work tracker, cache written on save (b084e9f) |
| Lost responses → self-conflicts (server and client) | medium | replay of the last success; client adopts identical server copy |
| Draft PUT: retired/mismatched version, 403 existence oracle, 2 MB cap | medium/low | 409 `version_retired`/`version_mismatch`, 404, 413 |
| Attachment cross-org uuid → 500 + orphan file; decompression bomb; inline downloads | medium/low | 409, row-before-file, pixel limit, CSP sandbox + attachment disposition |
| Reprojection not atomic; status drift; manifest misses grants | medium | per-submission transaction, status sync, inclusive cursor + touch on grants |
| Timers after stop, wipe notice lost, cache across users, repeater index keys | medium | disposed flag, sticky notice, cache clear, stable keys + pending-edit registry |
| Focus/title on route change, sticky footer obscuring focus, live-region noise | medium/low | RootLayout titles/focus, scroll-padding, quieter save status |
| Device-status timing oracle; preview `source` check; focus colour 2.1:1 | low | dummy hash, source check, `#b45309` |

Found by the E2E runs themselves: submission responses not wrapped in `{ submission }` (contract
mismatch), the repeater table widening the page on phones (sticky Submit off screen), and a race when
two designers create the same template concurrently (unique key) — all fixed with tests.

## Deviations and known issues
- Fortify endpoints live at the site root (`/auth/*`, plain JSON), as documented in the contract.
- The Field App omits `device`/`geo` on draft saves (optional in the contract).
- Attachments are fetched as blobs with credentials (no signed URLs): `<img>` cannot send
  `X-Organization-Id`. Revisit for offline caching in M6.
- A renderer unmounted by browser navigation mid-upload writes its last data plus the photo; it can
  overwrite a signature made on Review meanwhile (Review is disabled while uploads run).
- Preview iframe is same-origin (QUESTIONS #10, M8 task); devices are user-level (QUESTIONS #9);
  `app:reproject` skips `changes_requested` submissions (QUESTIONS #11).
- Offline outbox, Dexie and incremental manifest handling on the client are M6 scope (ADR 0006).
